# Dot Rigger

3D 휴머노이드 모델을 **고정 시점 2D 컷아웃 퍼펫**으로 변환하는 Godot 4.7 에디터 애드온.

프레임을 통째로 굽는 스프라이트 시트 방식이 아니라, 캐릭터를 파트로 쪼개
본에 붙이는 방식이다. 목적은 **장비 교체 시 리소스가 곱하기가 아니라 더하기로 늘어나게** 하는 것.

| 헬멧 1종 추가할 때 필요한 이미지 | |
|---|---|
| 프레임 베이크 (방향 x 애니 x 프레임) | 576장 |
| **컷아웃 부착 (이 도구)** | **1장** |

---

## 파이프라인

```
 .glb / .fbx
     │
     ├─ 본 웨이트 argmax ──────→ 정점마다 지배 본 → 파트 배정
     │                            (노드 하이어라키가 아니라 웨이트로 자른다.
     │                             리깅된 캐릭터는 팔·손이 별도 메쉬가 아니므로)
     │
     ├─ 메쉬 분해 ─────────────→ 파트별 ArrayMesh 15개 (발가락은 발에 합침)
     │                            경계 삼각형은 양쪽에 넣어 관절 겹침(bleed) 확보
     │
     ├─ 고정 각도 렌더 ────────→ 파트별 PNG (가려진 부분까지 온전히)
     │                            = 컷아웃에 필요한 형태
     │
     ├─ 본 투영 ───────────────→ 프레임별 2D 위치/각도/단축률/깊이
     │                            3D 애니메이션이 2D 애니메이션을 자동 저작
     │
     └─ 씬 생성 ───────────────→ Skeleton2D 퍼펫 + AnimationPlayer
                                  장비는 Bone2D 자식으로 붙임
```

## 사용법 — 에디터

1. `프로젝트 > 도구 > Dot Rigger (3D → 2D 컷아웃)`
   왼쪽 열의 섹션 제목을 누르면 **접었다 펼 수 있다**(도트화·파트 분리는 접힌 채 시작, 모델은 불러오면 접힘).
   **출력 폴더·베이크 버튼·진행바는 스크롤 밖 바닥에 항상 보인다.**
   창 배치: 왼쪽 = 설정, 위쪽 = **도트 스타일 바**(아웃라인), 가운데 = 프리뷰·파트 트리, 오른쪽 = 그리기 순서.
   **도트 아웃라인** — 상단 바의 `아웃라인` 에 1~3 을 넣으면 그 두께(도트 수)의 선이 생긴다.
   **선의 색은 `카툰` / `픽셀 퍼펙트` 둘 중 하나**(하나를 켜면 다른 하나가 꺼진다):
   - `카툰` — 선 전체를 옆 색 버튼의 **한 색**(보통 검정)으로 두른다. 만화 같은 또렷한 윤곽.
   - `픽셀 퍼펙트` — 선을 따로 두르는 게 아니라, 선의 도트마다 **바로 옆 몸 도트의 색을 어둡게** 해서 칠한다. 주황 살 옆은 짙은 주황,
     보라 관절 옆은 짙은 보라 — 가장자리가 그 자리 색의 결·톤을 따라간다(손으로 찍은 도트 그림의 색 있는 외곽선). 옆의 `%` = 어둡게 하는 정도
     (낮을수록 은은 · 높을수록 또렷, 기본 45%). 두께 1 권장.
   `전체 실루엣` 체크(기본 켬) = **캐릭터 전체 바깥 테두리에만** 선. 파트마다 선 색 "밑깔개"(`stretch/outline`, z −1)를 모든 파트 뒤에 깔고 파트가 그 위를 덮는 방식이라 관절 겹침에는 선이 없다.
   끄면 **파트마다** 선 — 관절이 겹치는 곳에도 선이 생긴다(종이 인형 느낌).
   2D 순서 프리뷰와 베이크 결과에 적용되고 3D 모드에는 안 보인다. 두께는 도트 단위라 게임에서 확대해도 같이 굵어진다.
   장비도 `equip()` 이 같은 밑깔개를 붙인다 — **장비 그림 가장자리에 선 두께만큼 투명 여백**을 둘 것(꽉 찬 그림은 바깥에 선을 그릴 자리가 없음).
   부드러운 도트 이동이 켜진 채 1배 크기로 그리면 선이 반투명하게 흐려진다(이 셰이더는 확대해서 그릴 때용 — 1배로 쓸 거면 부드러운 이동을 끌 것).
   CLI `--outline=1 --outline_color=000000 [--outline_parts] [--outline_style=pixel_perfect --outline_tone=0.45]`.
   **도트 격자 고정** — 상단 바의 `도트 격자 고정` 체크. 컷아웃 퍼펫을 게임에서 그냥 확대하면 파트가 돌 때 **도트가 기울어진 큰 사각형**으로
   보인다. 켜면 퍼펫을 **도트 해상도 그대로** 그린 뒤 통째로 확대해서, 돌아간 파트도 도트 격자에 다시 찍힌다 — 모든 도트가 같은 크기·같은 격자.
   위치도 정수 픽셀에 붙는다. 대신 1픽셀 미만의 움직임은 표현되지 않아 느린 동작에서 도트가 톡톡 튈 수 있다 —
   `부드러운 도트 이동` 과 반대 성격이라 켜면 그쪽은 꺼진다(칸이 잠김). 2D 순서 프리뷰에서 확인.
   **베이크하면 `puppet.tscn` 옆에 `puppet_pixel.tscn` 이 같이 나온다** — 게임에는 이걸 넣고 인스펙터의 `pixel_scale`(정수)로 키운다.
   자세한 건 아래 "도트 격자 고정으로 게임에 넣기". CLI `--pixel_grid`. (선 색 방식 `픽셀 퍼펙트` 와는 별개의 기능 — 같이 켜도 된다.)
2. **0. 프리셋** — 맞춰 놓은 설정을 `.tres` 로 저장/불러온다.
   각도·그리기 순서·애니 선택·도트 설정·출력 경로가 전부 들어간다.
   캐릭터마다 한 벌씩 만들어 두면 다시 맞출 필요가 없다.
   파일시스템 독에 그대로 보이고, 툴을 안 열어도 인스펙터에서 값을 볼 수 있다.
3. **1. 모델** — `.glb` 선택 후 `모델 불러오기 / 파트 분리`
   `추가 동작 폴더 (선택)` — 모델 파일 밖의 동작(Mixamo 에서 받은 `.fbx` 등)을 같은 캐릭터에 얹는다.
   **파일 이름 = 동작 이름**. 자세한 건 아래 "다른 출처의 동작 얹기 (Mixamo)".
4. **2. 시점** — 이 게임에서 캐릭터를 보여줄 **단 하나의 각도**를 정한다.
   프리셋(정측면/3⁄4/아이소…) 또는 Yaw·Pitch 직접 입력. **Pitch 양수 = 위에서 내려다봄.**
   3D 모드(2D 순서 꺼짐)에서는 프리뷰 오른쪽 위 **회전 기즈모**를 드래그해도 된다 — 값이 Yaw·Pitch 칸에 그대로 들어가서
   프리셋·베이크에 반영된다. 축 끝 동그라미를 누르면 그 방향에서 본다.
   `Ortho 크기` = 직교 카메라가 화면 세로로 담는 실제 높이(모델 단위). 작을수록 크게 찍힘, 0 = 자동.
   `자동 맞춤` 이 켜져 있으면 무시되고 화면에 꽉 차게 다시 맞춘다. 프리뷰 휠 확대와 달리 **베이크 결과가 바뀐다.**
   `캐릭터 이동 X / Y` = 도트 크기(Ortho)는 그대로 두고 캐릭터가 찍히는 위치만 캔버스 픽셀 단위로 옮긴다(+X 오른쪽, +Y 위).
   수영·눕기처럼 몸이 틀 밖으로 나가 잘릴 때 쓴다(아래가 잘리면 Y 를 + 로). 자동 맞춤이 켜져 있으면 무시된다.
   ⚠ 레스트 포즈가 틀 밖으로 나가면 **파트 그림 자체가 잘린 채 구워진다.** 해상도만 키워서는 안 넓어진다(같은 영역을 촘촘히 찍을 뿐).
5. **3. 도트화 > 해상도** — 캐릭터 한 마리가 들어갈 정사각 캔버스 크기.
   바로 아래 `여백`은 **픽셀 고정**이므로 저해상도로 갈수록 손해가 커진다.
   프리뷰 위에 `세로 채움 %` 가 뜨니 그걸 보고 여백을 줄일 것.

   | 해상도 | 여백 6px 일 때 세로 채움 |
   |---|---|
   | 256px | 96% |
   | 192px | 94% |
   | 96px | 88% |
   | 64px | 81% ← 여백을 2 정도로 줄일 것 |

6. **5. 리깅 애니메이션 (내보낼 동작 + 레스트 자세)** — 위 목록에서 `puppet.tscn` 의 AnimationPlayer 에 넣을 **동작**을 고른다
   (**그냥 클릭 = 그것만** — 검색으로 가려진 선택까지 풀린다 · **Ctrl·Shift + 클릭 = 추가** — 검색어를 바꿔 가며 여러 개를 모을 때.
   검색어를 바꾸는 것만으로는 선택이 안 풀리고, 고른 것은 아래 `선택 N개` 에 이름이 보인다).
   **`상하체 합성…`**(동작 목록 · `선택 비우기` 바로 아래 버튼) — 팝업이 열린다. **하체는 한 동작에서, 상체는 다른 동작에서** 가져와
   새 동작을 만든다(예: `Crouch_Fwd` + `Rifle_Aiming_Idle` = 앉아 걸으며 조준). 팝업에서: 왼쪽 = 상체로 칠 파트(기본 몸통·머리·두 팔),
   가운데 = 합성 목록(`추가`·`복제`·`삭제`·▲▼)과 편집 칸(이름 · 하체 동작 · 상체 동작 · 길이 맞춤 · 반복),
   **오른쪽 = 프리뷰** — 지금 고른 합성의 결과가 **`적용` 전에도 그 자리에서 재생**된다(▶ 재생 · 속도 ×1/½/¼ · 위치 슬라이더).
   하체·상체 동작, 길이 맞춤, 상체 파트를 바꾸면 바로 다시 만들어진다. 팝업이 떠 있는 동안 창의 재생은 멈춘다. `적용` 을 누르면
   만든 동작이 위 목록에 **하늘색**으로 나타나고 자동으로 골라진다 — 그 뒤로는 다른 애니와 똑같이 고르고 · 레스트가 잡히고 · 6번 세트에 담고 · 굽는다.
   길이 맞춤 4가지 = **누구의 시간에 맞추나 × 하체를 몇 번 돌리나**:
   `하체 시간에 상체를 맞춤 (하체 반복)`(기본 — 걸음 속도 그대로, 걸음을 여러 번 넣어 상체 길이와 비슷하게) ·
   `하체 시간에 상체를 맞춤 (하체 1번)`(걸음 한 번의 초가 전체 길이, 상체가 그 안에 들어가도록 빨라지거나 느려짐) ·
   `상체 시간에 하체를 맞춤 (하체 반복)`(사격·장전 속도 그대로, 그 안에 걸음을 여러 번) ·
   `상체 시간에 하체를 맞춤 (하체 1번)`(상체의 초가 전체 길이, 걸음 한 번이 그 길이로 늘어나거나 줄어듦).
   `하체 1번` 은 둘 다 한 번 하고 끝나는 동작(앉기 + 장전 등)을 같이 시작해 같이 끝낼 때 쓴다.
   **`방향 유지`(0~100%) · `각도 보정`(도)** — 앉기처럼 **골반이 앞으로 숙는 하체** 위에 상체를 얹으면 상체가 같이 숙는다
   (뼈의 각도가 부모인 골반 기준이라서. UAL `Crouch_Idle` 은 골반이 27° 숙어 있어 `Idle` 을 얹어도 몸통이 8° → 33° 로 숙고,
   몸통을 하체에서 가져오면 원래의 잠입 자세 49° 가 된다 — 어느 쪽도 바르게 앉은 자세가 아니다).
   `방향 유지` 100% = 몸통이 **상체 동작에서 보던 방향 그대로**(바르게 선 Idle 이면 앉아서도 바르게), 0% = 골반이 숙은 만큼 같이 숙음.
   `각도 보정` 은 그 위에 몸통을 더 돌린다(+ = 뒤로 젖힘 · − = 앞으로 숙임). 둘 다 프리뷰에 바로 보인다.
   새로 `추가` 한 합성은 100% 로 시작하고, 이 칸이 생기기 전에 만든 합성은 0%(그때 동작 그대로)로 열린다.
   합성은 3D 뼈대에서 하므로 몸통은 하체의 들썩임을 그대로 따라간다. 정의는 프리셋에 저장되고 `rig.json` 의 `composites` 에도 남는다.
   CLI `--composites="Crouch_Aim=Crouch_Fwd+Rifle_Aiming_Idle;…"`.
   **레스트 자세**(파트 그림을 찍는 자세 하나)는 `레스트 자세 자동 (고른 동작에서 찾기)` 가 켜져 있으면(기본)
   **고른 동작이나 시점이 바뀔 때마다 알아서 정해진다** — 고른 동작들의 프레임을 훑어 팔다리가 카메라를 향하지 않고
   화면과 가장 나란한 프레임을 고르고, 그 아래 "레스트 자동: Walk 88% (가장 눌린 파트 L_Foot 0.88)" 처럼 표시한다.
   **이 도구에서 결과를 가장 크게 좌우하는 값이다.** 어떤 파트가 레스트에서 카메라를 향해 짧게 찍히면 그 파트가 화면과
   나란해지는 동작마다 종아리가 얇아지고 발목이 꺾여 보인다(−55° 실측: `Idle` 레스트로 Walk 를 구우면 오른 종아리·발이
   35~60% 어긋남 → `Walk 25%` 레스트면 5%). 레스트와 동작이 같은 자세 계열이어야 자연스럽다는 뜻이고, 자동은 그걸 보장한다.
   자동을 끄면 아래 칸(애니·%·`이 애니에서 자세 찾기`·`고른 동작에서 찾기`)을 직접 고른다 —
   예: 내보내지 않는 `Crawl_Enter` 를 엎드리기 세트의 레스트로 쓰고 싶을 때. ⚠ T포즈는 측면에서 팔이 카메라를 향해 13x13 덩어리가 된다.
   **`지금 프레임을 레스트로`** — 재생을 `멈춤` 으로 두고 위치 슬라이더로 조각 그림이 가장 잘 나올 프레임을 고른 뒤 누르면
   그 애니·시점이 레스트 칸에 들어간다(자동은 꺼짐). 눈으로 보고 고르는 가장 빠른 방법.
   `(바인드 포즈)` 는 모델의 기본 자세(T포즈류)다 — 09-18 전에는 버그로 "마지막에 보던 프레임"이 찍혔다(02 C12).
   레스트가 **같은 자세 계열**이면 3D 대비 3~4%, 다른 계열(서서 쏴 ↔ 엎드려쏴)이면 16~22% 어긋난다(09-18 실측).
   **엎드리기(Crawl)·수영처럼 몸 방향이 다른 동작은 서 있는 자세로 못 찍는다** — 그 계열 동작만 골라(레스트는 자동으로 그 계열에서 나옴)
   **세트**(6번)로 담아 폴더를 나눠 굽는다. 게임에서 상태에 따라 퍼펫 씬을 바꾼다.
   아래 베이크 옵션 `샘플 FPS`·`단축 보정`·`부드러운 도트 이동`·`동작 평면화` 도 베이크 결과에 들어간다.
   **`동작 평면화 (2D 게임식)`** — 3D 를 그대로 투영하면 팔이 카메라 쪽으로 오갈 때 짧아졌다 길어져 종이가 접히듯("페이퍼맨") 보인다.
   켜면 각 파트의 회전을 게임 시점이 아니라 **동작 시점**(자동 = 게임 Yaw 에 가까운 측면 ±90°)에서 재서 팔다리가 화면 안에서만 돌고,
   위치는 관절에 고정(강체 2D 리그), 늘이기 없음, 힙의 위아래 들썩임만 남는다 — 2D 게임 캐릭터가 움직이는 방식.
   3D 와 똑같지는 않다(그게 목적). 옆으로 벌리는 동작이 많으면 `동작 시점 자동` 을 끄고 0(정면)을 넣어 본다.
   프리뷰·베이크 모두 적용되고, 평면화로 구운 애니와 3D 투영 애니는 같은 폴더에 섞이지 않는다(값의 뜻이 다름).
7. **6. 리깅 애니메이션 세트** — 5번 한 벌(동작 + 레스트)을 이름 붙여 담는 목록. 서기·엎드리기·수영처럼
   **몸 방향이 다른 계열은 파트 그림이 달라야 하므로 세트로 나눈다.**
   - `세트로 추가` — 지금 5번을 세트 하나로(이름을 비우면 레스트 애니 이름). 이름 = 출력 폴더 이름. 레스트가 자동이었으면 그것도 기억해서 구울 때 다시 찾는다.
   - 줄을 고르고 `세트 불러오기`(5번에 다시 펼침) → 고친 뒤 `덮어쓰기` · `삭제` · `▲▼`(굽는 순서 = sets.json 번호).
   - 세트가 **하나라도 있으면 베이크는 세트 전부를 순서대로** `<출력 폴더>/<세트 이름>/` 에 굽고 `<출력 폴더>/sets.json` 에
     번호·이름·폴더·레스트·동작·씬 경로를 남긴다. 세트가 없으면 5번 한 벌만 출력 폴더에.
   - **세트를 빼거나 이름을 바꾸고 다시 구우면 옛 세트 폴더는 알아서 치운다** — 지난번 `sets.json` 에 있었고 이번 목록에 없는 폴더만,
     그 안의 툴이 만든 파일(`puppet.tscn` · `puppet_pixel.tscn` · `rig.json` · `parts/` 의 PNG)만. 손으로 넣은 파일이 있으면 그 파일과 폴더는 남기고 알려 준다.
     지난번 `sets.json` 에 없던 폴더(다른 캐릭터를 같은 출력 폴더 아래에 구운 것 등)는 건드리지 않는다. 하나라도 굽기에 실패하면 아무것도 안 치운다.
   - **그리기 순서(자동/수동 목록)는 세트마다 저장된다** — 달리기 세트는 오른팔을 허벅지 뒤로, 걷기 세트는 앞으로 두는 식.
     세트를 불러오면 그 순서가 오른쪽 목록에 돌아오고, 목록 줄에 `순서 수동/자동` 이 보인다. 시점·도트화·베이크 옵션은 세트 공통이다. 프리셋에 같이 저장된다.
   - 예: `stand`(Idle·Walk·Jog) / `crawl`(Crawl_*) / `swim`(…) → 게임은 상태에 따라 `stand/puppet.tscn` ↔ `crawl/puppet.tscn` 을 바꿔 쓴다.
8. **7. 출력** — `res://` 경로 지정 후 `베이크`.
   `같은 폴더의 기존 애니 유지`(기본 켬)면 같은 폴더에 여러 번 구워도 **애니메이션 목록이 쌓인다**(같은 이름은 새로 구운 것으로 교체).
   단 레스트 포즈·시점·해상도·파트 구성이 예전과 다르면 섞을 수 없어서 예전 애니를 빼고 상태줄에 이유를 띄운다.

권장 순서: **시점 → 5번에서 동작 선택(레스트는 자동) → 세트로 추가 → 계열마다 반복 → 베이크 한 번**.

결과물:

```
<출력폴더>/
  parts/*.png     파트 스프라이트
  rig.json        파트 계층 / 피벗 / 프레임별 투영값 / 카메라 상태
  puppet.tscn     바로 쓸 수 있는 2D 퍼펫 (DRPuppet 스크립트 부착됨)
```

### ⚠ 창을 닫아도 살아 있습니다

X 를 눌러도 `hide()` 만 됩니다(`visible = false`). 불러온 모델·분해된 파트·설정이
그대로 남아서 다시 열면 이어서 작업할 수 있다. 대신 두 가지를 알아 둘 것:

- **숨어 있는 동안 SubViewport 가 렌더되지 않는다.** 베이크 중에 창을 닫으면 안 된다.
- **애드온 코드를 고친 뒤에는 다시 열어도 옛 인스턴스가 그대로 뜬다.**
  이때는 `프로젝트 > 도구 > Dot Rigger — 창 새로 만들기 (초기화)` 를 쓴다.
  그래도 이상하면 에디터를 재시작한다(`@tool` 스크립트는 구조가 바뀌면 핫리로드가 안 따라온다).

## 그리기 순서 (어느 파트를 앞에 그릴지)

창 오른쪽 **그리기 순서** 목록에서 정한다. **위가 뒤쪽, 아래가 앞쪽.**

목록의 한 줄은 **레이어**다. 기본 프로필은 파트 하나 = 한 줄(15줄)이다 — **발가락은 발에 합쳐져** 발은 레스트 모양 그대로 한 장이고
발목에서 회전만 한다(늘이기는 다른 파트처럼 켬). 발가락 분리 모드(`DRPartProfile.humanoid(true)` / `bake_cli --split_toes`)에서는
발가락(`L_Toe`/`R_Toe`)이 애니메이션에서 따로 접히고 목록에서는 발 줄에 묶여 항상 발 바로 위에 그려진다.

- **자동 (기본)** — 파트의 3D 깊이(head~tail 평균)로 매 프레임 정렬한다.
  걷기처럼 팔이 몸 앞뒤로 교차하는 동작이 자동으로 처리된다.
- **수동** — `▲ 뒤로` / `▼ 앞으로` 로 순서를 바꾸면 자동이 꺼지고,
  그 순서가 **모든 프레임에 고정**된다(프레임별 z 트랙을 만들지 않는다).
  한 각도로 고정된 게임에서는 이쪽이 예측 가능해서 더 안전한 경우가 많다.

**선택 = 프리뷰 대상.** 목록에서 고른 파트들만 프리뷰에 뜬다.

- 그냥 클릭 → 그 파트 하나만
- **Shift + 클릭 → 범위 선택**, **Ctrl + 클릭 → 하나씩 추가**
- 여러 개를 고르면 **그것들만** 3D 로 렌더된다.
  둘씩 골라 보면 어느 쪽이 앞이어야 하는지 바로 판단할 수 있다
  (예: `Torso` + `R_UpperArm` 만 켜서 어깨가 몸통에 어떻게 얹히는지 확인)
- `▲`/`▼` 는 **선택한 것 전부**를 한 칸씩 옮긴다. 떨어져 있어도 각각 이동하고,
  하나라도 끝에 닿으면 통째로 멈춘다(일부만 움직여 순서가 엉키는 걸 막기 위해).

CLI 에서는 `--zorder=Hips,Torso,Head,...` (레이어 이름, 뒤→앞) 로 지정한다. 발가락 이름을 적으면 발 줄로 바뀐다.
지정에서 빠진 줄은 목록 끝(= 가장 앞쪽)에 계층 순으로 붙는다.

### ⚠ 프리뷰에는 두 가지 모드가 있다

프리뷰 위 **`2D 순서`** 체크박스로 전환한다. 이걸 모르면 순서를 아무리 바꿔도
프리뷰가 안 변해서 "설정이 안 먹는다"고 오해하게 된다.

| 모드 | 무엇을 보여주나 | 그리기 순서 |
|---|---|---|
| **끔 (3D 렌더)** | GPU 깊이 버퍼가 픽셀마다 판정한 **정답** | **무시됨** |
| **켬 (2D 순서)** | 파트를 순서대로 겹쳐 그린 것 = **베이크 결과와 동일** | 반영됨 |

2D 순서 모드는 **베이크 캔버스보다 25% 넓게** 그리고 캔버스 틀을 얇은 선으로 표시한다 — 엎드리기·쭈그리기처럼 레스트 틀 밖으로
나가는 동작도 잘리지 않고 보인다(구운 퍼펫에는 원래 틀이 없다). 3D 모드는 베이크 캔버스 그대로라 틀 밖은 잘린다.
**레스트 자세만은 틀 안에 있어야 한다** — 그 그림이 파트가 되므로. 틀에 닿으면 `Ortho 크기`·`캐릭터 이동`·`자동 맞춤` 으로 잡는다.

작업 방식: 3D 로 "이렇게 보여야 한다"를 확인하고, 2D 로 바꿔서 순서를 맞춘다.
`▲`/`▼` 를 처음 누르면 자동으로 2D 모드로 전환된다(안 그러면 바꾼 게 안 보이므로).
파트 이미지는 캐시되므로 순서만 바꿀 때는 3D 렌더 없이 즉시 다시 그려진다.

**`▶ 재생` 은 두 모드 모두에서 동작한다.** 옆 드롭다운에서 **5번에서 고른 동작 중 무엇을 돌릴지** 고른다
(레스트 자세는 파트 그림 기준이라 그대로 두고 동작만 미리 본다. 고른 게 없으면 레스트 애니).
아래 줄의 **속도**(×1 · ×1/2 · ×1/4 · ×1/10 · 멈춤)로 느리게 보고, **슬라이더**로 원하는 시점으로 건너뛴다.
`멈춤`을 고르면 슬라이더로 프레임을 잡아 놓고 `2D 순서`를 켰다 껐다 하며 같은 시점의 3D 와 2D 를 비교할 수 있다 —
어느 파트가 어긋나는지 볼 때 이 방법이 가장 빠르다. 2D 모드의 재생은 캐시한 파트를
베이크된 씬과 똑같은 노드 구조(`bone → stretch → art`)에 붙이고 3D 본 투영값으로
움직이는 것이라, **구웠을 때 나올 결과를 그대로 미리 보는 것**과 같다.
지정한 그리기 순서도 적용된 채로 재생된다.

**재생하면 도트가 찌글거린다면** `부드러운 도트 이동`(기본 켬)을 확인한다. 켜져 있으면 2D 퍼펫을 프리뷰에 보이는 배율 그대로
그리고 도트 칸 경계만 화면 1픽셀 폭으로 섞어서, 1픽셀 미만 움직임이 깜빡임(옛날 TV 노이즈) 대신 매끄럽게 보인다.
끄면 예전처럼 캔버스 크기로 그린 뒤 확대한다(비교용). 베이크 씬의 파트·장비 스프라이트에도 같은 셰이더가 붙는다.

파트를 눌러 격리해서 본 뒤에는 **◀ 전체 보기** 버튼이나 트리 맨 위의
`＊ 전체 합성` 행으로 돌아온다.

## 장비 붙이기

```gdscript
var item := DREquipItem.new()
item.slot     = "helmet"
item.part     = "Head"          # 리그 파트 이름
item.texture  = preload("res://equip/helmet.png")
item.offset   = Vector2(81, 2)  # 레스트 포즈 기준 이미지 좌상단 캔버스 좌표
item.z_index  = 1000             # 절대 z. 파트는 뒤에서부터 10, 20, 30 … 을 받는다 — 그보다 크면 맨 앞, 5 면 맨 뒤
item.z_after_part = "Torso"     # (선택) "이 파트 바로 앞"에 그린다 — 있으면 z_index 대신 이걸 쓴다. 무기처럼 파트 **사이**에 끼울 때
$Puppet.equip(item)
```

- 파트 z 는 10 간격(`DRRigModel.Z_STEP`)이라 장비가 두 파트 사이(+5)에 낄 수 있다. `z_after_part` 로 장착하면 퍼펫이 그 파트의 z 를 매 프레임 따라가므로
  자동 순서(프레임마다 z 가 바뀜)로 구운 씬에서도 늘 그 파트 바로 앞이다. **09-21 이전에 구운 씬은 간격이 1** 이라 사이에 못 낀다(경고가 뜬다) → 다시 구울 것.
- 세트가 여러 벌이면 `DREquipSet`(세트 이름 → `DREquipItem`)으로 묶어 `DRPuppetSet.equip()` 에 준다 — 아래 "게임에서 쓰기".

- 같은 슬롯에 다시 `equip` 하면 교체된다.
- `follow_stretch = true`(기본)면 파트의 단축 보정을 같이 따른다.
  헬멧처럼 밀착된 것은 true, 매달린 것은 false.
- `tint_part(part, color)` 로 팔레트 스왑 흉내가 가능하다(가장 싼 배리에이션).
- 전체 실루엣 아웃라인으로 구운 퍼펫이면 장비에도 밑깔개가 자동으로 붙는다(`get_equipped_outline(slot)`, 빼면 같이 빠짐).
  장비 그림은 가장자리에 선 두께만큼 투명 여백을 둘 것.

**장비 이미지를 3D 에서 구울 때**는 캐릭터와 **완전히 같은 카메라 / 같은 레스트 포즈**
여야 정렬된다. 그래서 `rig.json` 의 `view` 에 카메라 트랜스폼까지 통째로 저장해 둔다
(`DRBaker.apply_view()` 로 복원).

## 게임에서 쓰기 — 세트 여러 벌을 캐릭터 하나처럼 (DRPuppetSet)

Unity 로 치면 **세트 1개 = 프리팹 1개 = Animator 1개**, 세트 안의 동작 = 그 Animator 의 클립이다.
자세 계열(서기 / 앉기 / 포복)은 파트 그림이 달라서 세트가 나뉘고 `puppet.tscn` 도 폴더별로 따로 나온다.
게임 코드가 그걸 일일이 갈아 끼우지 않게 `DRPuppetSet`(`runtime/dr_puppet_set.gd`)이 `sets.json` 을 읽어 **하나로 묶는다.**

```gdscript
var soldier := DRPuppetSet.new()
soldier.sets_json = "res://puppet/sets.json"
add_child(soldier)                           # 원점 = 두 발 사이의 바닥. 세트가 바뀌어도 발 자리가 같다
soldier.play("Rifle_Aiming_Idle")            # 어느 세트(폴더)에 있든 이름만 — 필요하면 퍼펫을 알아서 바꾼다
soldier.aim_enabled = true                   # 조준: 애니메이션 위에 몸통 각도를 더한다(머리·팔·총이 같이 돈다)
soldier.aim_target = get_global_mouse_position()   # 매 프레임. 위로 올리면 위를 겨눈다 · 등 뒤로 가면 돌아본다(auto_face)
```

| 속성 | 뜻 |
|---|---|
| `sets_json` | 세트 베이크가 남긴 `<출력 폴더>/sets.json` |
| `force_loop` | 모든 동작을 반복으로(Mixamo 동작은 가져올 때 반복 표시가 없다 — 제대로 하려면 임포트 설정의 Loop Mode) |
| `aim_enabled` · `aim_target` · `aim_limit_deg`(기본 35) · `aim_speed` · `aim_part`(기본 `Torso`) | 조준. 각도는 `get_aim_degrees()` |
| `auto_face` · `baked_facing_right` | 목표가 등 뒤면 좌우 반전. 캐릭터를 왼쪽을 보게 구웠으면 `baked_facing_right` 를 끈다 |
| `get_animations()` · `has_animation()` · `current_animation()` · `current_set()` · `get_puppet()` · `get_animation_player()` | 조회 |

- **시험장**: `res://test/puppet_test.tscn` 을 열고 **F6**. 숫자 1~9 = 동작 바꾸기, 마우스 = 조준(이름에 aim·rifle·fir·shoot·pistol 이 든 동작일 때 자동),
  `A` 조준 자동/켬/끔 · `F` 좌우 반전 · `+`/`−` 확대 · `L` 반복 · `R` 다시 구운 뒤 다시 읽기 · **`E` 장비 바꿔 들기**(`res://equip/*/equip.json` 으로 구워 둔 무기를 차례로).
  병사는 보통 시험장 스크립트가 코드로 만든다. 그 씬 안에 `DRPuppetSet` 노드를 **직접 놓아 두면**(노드 추가에서 `DRPuppetSet` 검색, 또는 Node2D 에
  `dr_puppet_set.gd` 를 끌어다 붙임) 새로 만들지 않고 그 노드를 그대로 쓴다 — 놓은 자리·크기·인스펙터 값 그대로, 키와 마우스가 그 노드를 움직인다.
- **세트를 어떻게 나누나**: 같은 자세 계열의 동작은 **한 세트에 같이**(5번에서 Ctrl 클릭으로 여러 개 고르고 `세트로 추가` 한 번) —
  그래야 그 세트의 `puppet.tscn` 하나에 동작이 다 들어가고, 같은 세트 안의 전환은 퍼펫을 안 바꿔서 매끄럽다.
  동작 하나마다 세트를 만들면 동작을 바꿀 때마다 파트 그림이 통째로 바뀐다(`DRPuppetSet` 이 돌려는 주지만 전환이 툭 끊긴다).
- 조준은 AnimationPlayer 를 수동(MANUAL)으로 돌려 "지난 프레임에 더한 각도를 빼고 → 애니 진행 → 새 각도를 더함" 순서를 지킨다 — 애니가 멈춰 있어도 각도가 쌓이지 않는다.
- **장비는 `soldier.equip(equip_set)` 한 번이면 모든 세트에 붙는다.** 세트마다 레스트 자세의 손 방향이 달라 장비 그림도 세트마다 한 장이므로,
  그 그림들을 `DREquipSet`(`items`: 세트 이름 → `DREquipItem`)으로 묶어 준다. 동작이 바뀌어 세트가 넘어가도 그대로 들려 있고, 같은 슬롯에 다른 걸 주면 바꿔 든다(무기 교체).
  그 세트용 그림이 없는 세트는 그 슬롯이 빈다. `soldier.unequip("weapon")` · `soldier.get_equipped("weapon")`. `reload()` 뒤에도 다시 장착된다.
- 게임을 내보낼 때는 `sets.json` · `rig.json` 이 같이 들어가게 내보내기 필터에 `*.json` 을 넣을 것.
- 검사: `tools/puppet_set_check_cli.gd`.

## 도트 격자 고정으로 게임에 넣기

`도트 격자 고정` 을 켜고 구우면 출력 폴더에 두 씬이 나온다.

| 씬 | 쓰임 |
|---|---|
| `puppet.tscn` | 퍼펫 본체(DRPuppet). 경계 섞기(부드러운 도트 이동)는 꺼진 채로 구워진다 |
| `puppet_pixel.tscn` | **게임에 넣을 것.** 루트 `DRPixelPuppet` → `View`(SubViewport: 투명 · nearest · 정수 픽셀 맞춤, 안에 `puppet.tscn` 인스턴스) + `Screen`(그 그림을 보여 주는 Sprite2D) |

```gdscript
var soldier := preload("res://puppet/stand/puppet_pixel.tscn").instantiate() as DRPixelPuppet
add_child(soldier)
soldier.pixel_scale = 3                 # 도트 1개 = 화면 3픽셀. 정수만(노드 scale 로 키우지 말 것)
soldier.play("Walk")
soldier.get_puppet().equip(helmet)      # 장비는 안쪽 퍼펫에
```

- 원점은 `puppet.tscn` 과 같다(베이크 캔버스 왼쪽 위) → 두 씬을 바꿔 끼워도 자리가 같다.
- `View` 의 크기는 베이크가 **레스트 + 구운 모든 애니의 모든 프레임**에서 파트 그림이 닿는 범위를 재서 정한다(`rig.json` 의 `pixel_view`).
  장비가 몸 밖으로 많이 나가 잘리면 인스펙터의 `extra_margin` 을 키운다(화면의 자리는 그대로).
- 캐릭터마다 작은 SubViewport 하나를 더 그린다 — 수십 명은 문제없다.
- **게임 전체를 저해상도로 그리는 프로젝트**(프로젝트 설정 → 표시 → 창 → 스트레치 모드 `viewport`)라면 이 래퍼가 필요 없다 —
  `puppet.tscn` 을 배율 1 로 쓰면 화면 전체가 같은 격자다. 이 래퍼는 고해상도 화면에 캐릭터만 도트로 키워 그릴 때 쓴다.
- 1픽셀 미만의 움직임이 사라지므로 Idle 처럼 느린 동작은 도트가 톡톡 튄다. 그게 싫으면 끄고 `부드러운 도트 이동` 을 쓴다(둘은 반대 성격).

## 다른 출처의 동작 얹기 (Mixamo)

Unity 의 **Humanoid** 에 해당하는 것이 Godot 의 **BoneMap + SkeletonProfileHumanoid** 다. 차이는 Unity 는 실행 중에 Avatar 가
바꿔 주고, Godot 는 **가져올 때** 본 이름과 기준 자세를 표준 휴머노이드로 바꿔 저장한다는 것. 그래서 **캐릭터 파일과 동작 파일
양쪽에** 지정해야 한다. 전부 Godot 에디터 안에서 하고 다른 프로그램은 필요 없다(FBX 도 Godot 가 직접 읽는다).

이 저장소에는 이미 해 둔 것이 `source3d/` 에 있다:

| 파일 | 뜻 |
|---|---|
| `source3d/UAL1_humanoid.glb` | `models/UAL1.glb` 와 같은 파일. 임포트 설정에 `bonemap_ual.tres` 가 지정돼 본 이름이 표준(`Hips`, `LeftUpperArm` …)이다. 기존 동작 120개는 그대로(관절 위치 차이 5mm 미만 — `retarget_check_cli`) |
| `source3d/mixamo/*.fbx` | Mixamo 동작(스킨 없이 받은 것). 임포트 설정에 `bonemap_mixamo.tres` 지정 |
| `source3d/bonemap_ual.tres` · `bonemap_mixamo.tres` | 짝 맞춤 표. `tools/make_bonemap_cli.gd` 로 다시 만들 수 있다 |

**Dot Rigger 에서 쓰기**: 모델 = `res://source3d/UAL1_humanoid.glb`, 추가 동작 폴더 = `res://source3d/mixamo` → `모델 불러오기`.
동작 목록에 `Firing_Rifle`, `Rifle_Aiming_Idle` … 이 기존 120개와 같이 뜬다. 프리셋에 폴더도 저장된다.

**Mixamo 동작을 더 받을 때**

1. Mixamo 에서 **같은 캐릭터를 고른 채로**, `Without Skin`, 이동 동작은 **`In Place` 체크**해서 FBX 로 받는다.
   (`In Place` 를 안 켜면 캐릭터가 화면 밖으로 걸어 나간다. 게임에서는 코드가 위치를 옮긴다.)
2. 파일 이름을 **쓰고 싶은 동작 이름**으로 바꿔(`Rifle_Reload.fbx`) `source3d/mixamo/` 에 넣는다. Mixamo 는 파일마다
   동작 이름이 전부 `mixamo.com` 이라 파일 이름을 동작 이름으로 쓴다(공백은 `_` 로 바뀜).
3. 파일시스템 독에서 그 파일을 더블클릭 → 고급 임포트 설정 → 왼쪽 트리의 `Skeleton3D` → 오른쪽 `Retarget` 의 `Bone Map` 칸 →
   `불러오기` → `source3d/bonemap_mixamo.tres` → `다시 가져오기`. 사람 모양 그림의 점이 전부 초록이면 된 것.
4. Dot Rigger 창에서 `모델 불러오기` 를 다시 누른다. 짜 둔 **그리기 순서·고른 동작·레스트는 그대로 남는다**
   (상태줄에 `· 유지: 그리기 순서, 고른 동작 N개`). 모델 칸을 `models/UAL1.glb` 에서 `source3d/UAL1_humanoid.glb` 로 바꿀 때도 마찬가지.

- 상태줄에 `⚠ 추가 동작 경고 … 뼈 이름이 모델과 하나도 안 맞아 뺌` 이 뜨면 3번을 안 했거나 **본 이름 접두사가 다른 것**이다.
  Mixamo 는 고른 캐릭터에 따라 `mixamorig:` · `mixamorig9:` 처럼 번호가 붙는다(지금 파일들은 `mixamorig9`). 접두사가 다른 파일은
  `make_bonemap_cli.gd -- --kind=mixamo --prefix=mixamorig_ --out=...` 로 표를 하나 더 만들거나, 3번에서 `새 BoneMap` 을 골라 자동 짝 맞춤을 쓴다.
- 되풀이 재생할 동작(조준 대기 등)은 고급 임포트 설정의 그 애니메이션에서 `Loop Mode` 를 켠다.
- 두 캐릭터의 체형이 달라 **양손 간격이 원본과 다르다**(UAL 은 어깨가 좁아 Mixamo 원본보다 25% 좁음). 동작 내내 일정하므로
  소총이 손 사이에서 미끄러지지는 않는다 — 소총 그림을 이 캐릭터의 손 간격에 맞춰 그리면 된다.
- 검사: `tools/retarget_check_cli.gd` (기존 동작 보존 · 파일 전부 경고 없이 얹힘 · 힙 높이 · 굽기).

## 다른 리그 / 다른 종류

본 이름 매핑은 `core/part_profile.gd` 의 규칙 배열 하나다.
UE 마네킹(`upperarm_l`)과 Mixamo(`mixamorig:LeftArm`) 를 기본 지원한다.
차량·중장비는 규칙만 새로 쓰면 나머지 파이프라인은 그대로 돈다.

```gdscript
{"pattern": "(turret|포탑)", "part": "Turret", "sided": false}
```

`layer` 를 주면 움직임은 따로, 그리기 순서는 다른 파트 줄에 묶는다(발가락이 이 방식):

```gdscript
{"pattern": "(ball|toe)", "part": "Toe", "sided": true, "layer": "Foot"}
```

## 알려진 한계

- **스프라이트 단위 정렬은 픽셀 단위 깊이를 재현하지 못한다.**
  3D 에서는 z버퍼가 픽셀마다 판정하지만 2D 는 파트 한 장을 통째로 앞/뒤에 놓는다.
  어깨가 몸통을 감아 도는 곳처럼 **한 파트가 동시에 앞이기도 뒤이기도 한**
  경우에는 어떤 순서로도 완벽히 맞지 않는다. 실측
  (`tools/compare_cli.gd`, UAL1 192px, Idle 정지, 자동 순서, 2026-09-15 도트 셰이더 깊이 수정 후):

  | 시점 | 3D 렌더 대비 불일치 |
  |---|---|
  | 정측면 (yaw 90) | 9.4% |
  | yaw −45 | **3.9%** |
  | yaw −55 | 7.8% |
  | yaw −65 | 11.4% |

  **각도에 따라 2~3배 차이가 난다** — 이 모델·레스트 포즈에서는 −45° 가 가장 잘 맞았다. 단 레스트 정지 자세만 본 값이라,
  동작이 화면 안에서 일어나는지(걷기·공중제비는 측면이 유리)와 같이 보고 정할 것. 순서 문제는 순서로 푼다(관절 겹침 링으로는 안 고쳐짐).
  > 09-14 에 쟀던 "각도별 4.3~5.9%, 차이 작음"은 3D 렌더가 깊이를 안 쓰던 셰이더 버그(뒤쪽 면이 비침) 상태의 틀린 기준이었고,
  > 그 전의 12~22% 는 자세 드리프트까지 섞인 값이다. 불일치가 뭉치는 곳(3⁄4 사타구니, 정측면 몸통 뒤 팔 경계)도 09-14 기준이라 다시 확인이 필요하다.
- **깊이 회전은 표현 못 한다.** 컷아웃의 근본 한계. 파트가 카메라 쪽으로 돌면
  화면상 길이가 줄어드는데(단축), 이건 `stretch` 노드로 근사할 뿐이다.
  그래서 3D 를 그대로 투영하면 3⁄4 시점에서 팔이 앞뒤로 오갈 때 종이가 접히듯 보인다 — 2D 게임 느낌을 원하면
  **`동작 평면화`** 를 켠다(각도만 측면에서 재고 길이는 고정). 대신 3D 와 실루엣이 30~50% 어긋나는 건 감수한다(2D 리그가 원래 그렇다).
  베이크 후 출력되는 `[단축률 진단]` 을 볼 것 — **1.00 에서 멀수록 그 파트는
  이 각도에서 위험**하고, 보통 레스트 포즈를 바꾸면 개선된다.
  측면 시점 기준 다리·몸통은 ±2%, 팔은 20~30% 나온다.
  **각도는 "동작이 화면 안에서 일어나는 방향"으로 고른다.** 예: `BackFlip`(뒤공중제비, 좌우축 회전)을
  yaw −38° 로 구우면 몸이 카메라 쪽으로 넘어와 몸통이 0.49배·머리 0.57배·손 0.16배까지 줄어
  **종이 한 장이 접히는 것처럼** 보인다. 같은 동작을 측면(yaw 90)으로 구우면 몸통·머리 1.00배 그대로
  엉덩이가 화면 안에서 398° 돈다(팔은 옆으로 뻗어 측면에서도 줄어듦). (2026-09-15 실측, 184px, 레스트 `Idle_LookAround`)
- **발가락은 접히지 않는다(기본).** 184px 에서 발가락은 2~4픽셀이라 따로 꺾으면 1픽셀도 안 되게 꿈틀거리기만 해서
  발에 합쳤다. 발은 레스트 모양 그대로 한 장, 발목에서 회전만 한다. 발끝이 접히는 모습이 꼭 필요하면 `--split_toes`.
- **발이 부풀었다 줄고 휘청거리면(지렁이)** 두 가지가 겹친 것이다: ① 단축 보정이 발을 1.6배까지 늘이던 것 → 발은 **±15% 로 제한**(기본 프로필 `stretch_limit`),
  ② 발이 카메라를 향해 화면에서 짧아지면 2D 각도가 잡음처럼 튀는 것 → 손·발은 단축률 0.45 아래에서 **회전을 레스트 쪽으로 누른다**(`angle_fade`).
  그래도 심하면 레스트 자동이 고른 자세의 "가장 눌린 파트" 가 발인지 보고(발이 0.5 아래면 그 시점 자체가 발에 불리), `동작 평면화` 를 켜면 늘이기가 아예 없다.
- **도트를 확대해서 연속 재생하면 경계가 깜빡일 수 있다(옛날 TV 노이즈).** 60fps 로 매 프레임 1픽셀 미만씩 움직이면
  도트 칸이 통째로 켜졌다 꺼졌다 한다(이미 도트인 조각을 다시 돌리고 옮기며 한 번 더 뽑기 때문. 픽셀 스냅은 오히려 나빠짐).
  `부드러운 도트 이동`(기본 켬)이 칸 안쪽은 또렷하게 두고 칸 경계만 화면 1픽셀 폭으로 섞어서 줄인다 —
  Idle 실측 노이즈 25.5 → 4.9, 움직임 양은 그대로. 단 **게임이 캐릭터를 확대해서 그릴 때만** 효과가 있고
  (저해상도 화면에 1:1 로 그린 뒤 화면 전체를 키우면 효과 없음), 뛰기처럼 빠른 동작에서 남는 변화는 3D 렌더와 같은 수준이라 더 줄지 않는다.
- 캐릭터 키 96px 이하에서 **손가락 단위 파트는 무의미**하다(손이 2~3픽셀).
  기본 프로필이 손가락 20본을 `Hand` 하나로 접는 이유.
