# Dot Rigger

3D 휴머노이드 모델을 **고정 시점 2D 컷아웃 퍼펫**으로 변환하는 Godot 4.7 에디터 애드온.

프레임을 통째로 굽는 스프라이트 시트 방식이 아니라, 캐릭터를 파트로 쪼개
본에 붙이는 방식이다. 목적은 **장비 교체 시 리소스가 곱하기가 아니라 더하기로 늘어나게** 하는 것.

| 헬멧 1종 추가할 때 필요한 이미지 | |
|---|---|
| 프레임 베이크 (방향 x 애니 x 프레임) | 576장 |
| **컷아웃 부착 (이 도구)** | **1장** |

---

## 파이프라인

```
 .glb / .fbx
     │
     ├─ 본 웨이트 argmax ──────→ 정점마다 지배 본 → 파트 배정
     │                            (노드 하이어라키가 아니라 웨이트로 자른다.
     │                             리깅된 캐릭터는 팔·손이 별도 메쉬가 아니므로)
     │
     ├─ 메쉬 분해 ─────────────→ 파트별 ArrayMesh 15개 (발가락은 발에 합침)
     │                            경계 삼각형은 양쪽에 넣어 관절 겹침(bleed) 확보
     │
     ├─ 고정 각도 렌더 ────────→ 파트별 PNG (가려진 부분까지 온전히)
     │                            = 컷아웃에 필요한 형태
     │
     ├─ 본 투영 ───────────────→ 프레임별 2D 위치/각도/단축률/깊이
     │                            3D 애니메이션이 2D 애니메이션을 자동 저작
     │
     └─ 씬 생성 ───────────────→ Skeleton2D 퍼펫 + AnimationPlayer
                                  장비는 Bone2D 자식으로 붙임
```

## 사용법 — 에디터

1. `프로젝트 > 도구 > Dot Rigger (3D → 2D 컷아웃)`
2. **0. 프리셋** — 맞춰 놓은 설정을 `.tres` 로 저장/불러온다.
   각도·그리기 순서·애니 선택·도트 설정·출력 경로가 전부 들어간다.
   캐릭터마다 한 벌씩 만들어 두면 다시 맞출 필요가 없다.
   파일시스템 독에 그대로 보이고, 툴을 안 열어도 인스펙터에서 값을 볼 수 있다.
3. **1. 모델** — `.glb` 선택 후 `모델 불러오기 / 파트 분리`
4. **2. 시점** — 이 게임에서 캐릭터를 보여줄 **단 하나의 각도**를 정한다.
   프리셋(정측면/3⁄4/아이소…) 또는 Yaw·Pitch 직접 입력. **Pitch 양수 = 위에서 내려다봄.**
   3D 모드(2D 순서 꺼짐)에서는 프리뷰 오른쪽 위 **회전 기즈모**를 드래그해도 된다 — 값이 Yaw·Pitch 칸에 그대로 들어가서
   프리셋·베이크에 반영된다. 축 끝 동그라미를 누르면 그 방향에서 본다.
   `Ortho 크기` = 직교 카메라가 화면 세로로 담는 실제 높이(모델 단위). 작을수록 크게 찍힘, 0 = 자동.
   `자동 맞춤` 이 켜져 있으면 무시되고 화면에 꽉 차게 다시 맞춘다. 프리뷰 휠 확대와 달리 **베이크 결과가 바뀐다.**
   `캐릭터 이동 X / Y` = 도트 크기(Ortho)는 그대로 두고 캐릭터가 찍히는 위치만 캔버스 픽셀 단위로 옮긴다(+X 오른쪽, +Y 위).
   수영·눕기처럼 몸이 틀 밖으로 나가 잘릴 때 쓴다(아래가 잘리면 Y 를 + 로). 자동 맞춤이 켜져 있으면 무시된다.
   ⚠ 레스트 포즈가 틀 밖으로 나가면 **파트 그림 자체가 잘린 채 구워진다.** 해상도만 키워서는 안 넓어진다(같은 영역을 촘촘히 찍을 뿐).
5. **3. 도트화 > 해상도** — 캐릭터 한 마리가 들어갈 정사각 캔버스 크기.
   바로 아래 `여백`은 **픽셀 고정**이므로 저해상도로 갈수록 손해가 커진다.
   프리뷰 위에 `세로 채움 %` 가 뜨니 그걸 보고 여백을 줄일 것.

   | 해상도 | 여백 6px 일 때 세로 채움 |
   |---|---|
   | 256px | 96% |
   | 192px | 94% |
   | 96px | 88% |
   | 64px | 81% ← 여백을 2 정도로 줄일 것 |

6. **5. 레스트 포즈** — 파트 그림(조각)을 찍는 **자세 하나**. 동작으로 들어가지 않는다(동작은 6번).
   **이 도구에서 결과를 가장 크게 좌우하는 값이다.** 어떤 파트가 이 자세에서 카메라를 향해 짧게 찍히면,
   그 파트가 화면과 나란해지는 동작마다 종아리가 얇아지고 발목이 꺾여 보인다
   (−55° 실측: `Idle` 은 오른발이 카메라를 향해 Walk 의 오른 종아리·발이 35~60% 어긋남 → `Walk 25%` 를 레스트로 쓰면 5%).
   → 자세 찾기 버튼 두 개(상태줄에 가장 눌린 파트와 점수가 뜬다. 슬라이더는 그 애니의 몇 % 시점인지):
   - **`이 애니에서 자세 찾기`** — 위에 고른 애니 **안에서** 가장 좋은 시점만 찾는다. 애니는 안 바뀐다.
     (예: 레스트를 `Crawl_Bwd` 로 두고 누르면 `Crawl_Bwd` 의 몇 % 가 좋은지)
   - **`6번 동작에서 찾기`** — 6번에서 고른 동작들(없으면 전체)을 훑어 **어느 애니의 몇 %** 가 가장 좋은지 찾는다. 애니가 바뀔 수 있다.
     6번에 `Walk` 만 남아 있으면 `Walk` 로 바뀐다.
   ⚠ T포즈는 측면에서 팔이 카메라를 향해 13x13 덩어리가 된다.
   **엎드리기(Crawl)·수영처럼 몸 방향이 다른 동작은 서 있는 자세로 못 찍는다** — 그 계열 애니를 레스트로 골라 `이 애니에서 자세 찾기`,
   6번에는 그 계열 동작만, **다른 출력 폴더**(예: `res://puppet_crawl`)에 굽는다. 게임에서 상태에 따라 퍼펫 씬을 바꾼다.
7. **6. 내보낼 애니메이션** — `puppet.tscn` 의 AnimationPlayer 에 넣을 **동작**을 고른다(Ctrl·Shift 로 여러 개).
   5번 레스트 포즈는 조각 그림을 찍는 자세일 뿐 동작으로 들어가지 않는다 — Idle 동작도 넣으려면 여기서 고른다.
   검색어를 바꿔 가며 골라도 선택이 쌓이고, 목록 아래 `선택 N개` 에 이름이 보인다.
   같은 칸의 `단축 보정`, `부드러운 도트 이동`(재생 시 도트 찌글거림을 줄이는 셰이더, 기본 켬)도 베이크 결과에 들어간다.
8. **7. 출력** — `res://` 경로 지정 후 `베이크`.
   `같은 폴더의 기존 애니 유지`(기본 켬)면 같은 폴더에 여러 번 구워도 **애니메이션 목록이 쌓인다**(같은 이름은 새로 구운 것으로 교체).
   단 레스트 포즈·시점·해상도·파트 구성이 예전과 다르면 섞을 수 없어서 예전 애니를 빼고 상태줄에 이유를 띄운다.

권장 순서: **시점 → 6번 동작 선택 → 5번 `6번 동작에서 찾기`(또는 레스트 애니를 정하고 `이 애니에서 자세 찾기`) → 베이크**.
자세 계열(서기 / 엎드리기 / 수영)마다 이 순서를 폴더를 바꿔 반복한다.

결과물:

```
<출력폴더>/
  parts/*.png     파트 스프라이트
  rig.json        파트 계층 / 피벗 / 프레임별 투영값 / 카메라 상태
  puppet.tscn     바로 쓸 수 있는 2D 퍼펫 (DRPuppet 스크립트 부착됨)
```

### ⚠ 창을 닫아도 살아 있습니다

X 를 눌러도 `hide()` 만 됩니다(`visible = false`). 불러온 모델·분해된 파트·설정이
그대로 남아서 다시 열면 이어서 작업할 수 있다. 대신 두 가지를 알아 둘 것:

- **숨어 있는 동안 SubViewport 가 렌더되지 않는다.** 베이크 중에 창을 닫으면 안 된다.
- **애드온 코드를 고친 뒤에는 다시 열어도 옛 인스턴스가 그대로 뜬다.**
  이때는 `프로젝트 > 도구 > Dot Rigger — 창 새로 만들기 (초기화)` 를 쓴다.
  그래도 이상하면 에디터를 재시작한다(`@tool` 스크립트는 구조가 바뀌면 핫리로드가 안 따라온다).

## 사용법 — 커맨드라인

에디터 없이 배치 처리할 때. **`--headless` 는 렌더가 안 되므로 쓰면 안 된다**
(창이 떠야 SubViewport 가 그려진다).

```bash
Godot.exe --path <프로젝트> --resolution 320x200 \
  --script res://addons/dot_rigger/tools/bake_cli.gd -- \
  --model=res://models/UAL1.glb --out=res://puppet \
  --yaw=90 --rest=Idle --size=192 --fps=12 --anims=Idle,Jog_Fwd
```

| 도구 | 용도 |
|---|---|
| `tools/bake_cli.gd` | 베이크. `--diag` 만 주면 본→파트 매핑만 출력(렌더 없음, headless 가능). `--nostretch` 단축 보정 끔 · `--nosmooth` 부드러운 도트 셰이더 끔 · `--split_toes` 발가락 따로 꺾기 · `--fresh` 같은 폴더의 예전 애니를 이어 담지 않음 |
| `tools/preview_cli.gd` | 생성된 `puppet.tscn` 을 실제로 재생해 프레임 캡처 |
| `tools/equip_test_cli.gd` | 장비 부착 검증 (장비 스프라이트 머티리얼이 본체와 같은지 포함) |
| `tools/compare_cli.gd` | 같은 각도에서 **3D 렌더 vs 2D 순서 합성**을 나란히 뽑고 불일치 %를 측정. 각도 고를 때 유용 |
| `tools/drift_check_cli.gd` | 자세가 프레임 사이에 흐르지 않는지 검사 |
| `tools/rootbone_check_cli.gd` | 파트 피벗(루트 본)이 살이 붙고 실제로 움직이는 본인지 검사. `root` 같은 기준점 본이 잡히면 실패 |
| `tools/layer_check_cli.gd` | 기본 프로필에서 발가락이 발에 합쳐지고 발은 늘이기 없이 발목 회전만 하는지 + 발가락 분리 모드에서 발가락이 따로 접히고 그리기 순서에서는 발 줄에 묶이는지 (구운 씬·rig.json 까지) |
| `tools/anim_merge_check_cli.gd` | 같은 폴더에 여러 번 구우면 애니가 쌓이는지 · 같은 이름은 교체되는지 · 레스트 포즈가 다르면 섞지 않는지 · 유지를 끄면 이번 것만 남는지 |
| `tools/ui_smoke_cli.gd` | 에디터 창 UI 코드 경로 + 배치 스모크 테스트 |

## 그리기 순서 (어느 파트를 앞에 그릴지)

창 오른쪽 **그리기 순서** 목록에서 정한다. **위가 뒤쪽, 아래가 앞쪽.**

목록의 한 줄은 **레이어**다. 기본 프로필은 파트 하나 = 한 줄(15줄)이다 — **발가락은 발에 합쳐져** 발은 레스트 모양 그대로 한 장이고
발목에서 회전만 한다(늘이기 없음). 발가락 분리 모드(`DRPartProfile.humanoid(true)` / `bake_cli --split_toes`)에서는
발가락(`L_Toe`/`R_Toe`)이 애니메이션에서 따로 접히고 목록에서는 발 줄에 묶여 항상 발 바로 위에 그려진다.

- **자동 (기본)** — 파트의 3D 깊이(head~tail 평균)로 매 프레임 정렬한다.
  걷기처럼 팔이 몸 앞뒤로 교차하는 동작이 자동으로 처리된다.
- **수동** — `▲ 뒤로` / `▼ 앞으로` 로 순서를 바꾸면 자동이 꺼지고,
  그 순서가 **모든 프레임에 고정**된다(프레임별 z 트랙을 만들지 않는다).
  한 각도로 고정된 게임에서는 이쪽이 예측 가능해서 더 안전한 경우가 많다.

**선택 = 프리뷰 대상.** 목록에서 고른 파트들만 프리뷰에 뜬다.

- 그냥 클릭 → 그 파트 하나만
- **Shift + 클릭 → 범위 선택**, **Ctrl + 클릭 → 하나씩 추가**
- 여러 개를 고르면 **그것들만** 3D 로 렌더된다.
  둘씩 골라 보면 어느 쪽이 앞이어야 하는지 바로 판단할 수 있다
  (예: `Torso` + `R_UpperArm` 만 켜서 어깨가 몸통에 어떻게 얹히는지 확인)
- `▲`/`▼` 는 **선택한 것 전부**를 한 칸씩 옮긴다. 떨어져 있어도 각각 이동하고,
  하나라도 끝에 닿으면 통째로 멈춘다(일부만 움직여 순서가 엉키는 걸 막기 위해).

CLI 에서는 `--zorder=Hips,Torso,Head,...` (레이어 이름, 뒤→앞) 로 지정한다. 발가락 이름을 적으면 발 줄로 바뀐다.
지정에서 빠진 줄은 목록 끝(= 가장 앞쪽)에 계층 순으로 붙는다.

### ⚠ 프리뷰에는 두 가지 모드가 있다

프리뷰 위 **`2D 순서`** 체크박스로 전환한다. 이걸 모르면 순서를 아무리 바꿔도
프리뷰가 안 변해서 "설정이 안 먹는다"고 오해하게 된다.

| 모드 | 무엇을 보여주나 | 그리기 순서 |
|---|---|---|
| **끔 (3D 렌더)** | GPU 깊이 버퍼가 픽셀마다 판정한 **정답** | **무시됨** |
| **켬 (2D 순서)** | 파트를 순서대로 겹쳐 그린 것 = **베이크 결과와 동일** | 반영됨 |

작업 방식: 3D 로 "이렇게 보여야 한다"를 확인하고, 2D 로 바꿔서 순서를 맞춘다.
`▲`/`▼` 를 처음 누르면 자동으로 2D 모드로 전환된다(안 그러면 바꾼 게 안 보이므로).
파트 이미지는 캐시되므로 순서만 바꿀 때는 3D 렌더 없이 즉시 다시 그려진다.

**`▶ 재생` 은 두 모드 모두에서 동작한다.** 옆 드롭다운에서 **6번에서 고른 애니 중 무엇을 돌릴지** 고른다
(레스트 포즈는 파트 그림 기준이라 그대로 두고 동작만 미리 본다. 6번에서 고른 게 없으면 레스트 포즈 애니). 2D 모드의 재생은 캐시한 파트를
베이크된 씬과 똑같은 노드 구조(`bone → stretch → art`)에 붙이고 3D 본 투영값으로
움직이는 것이라, **구웠을 때 나올 결과를 그대로 미리 보는 것**과 같다.
지정한 그리기 순서도 적용된 채로 재생된다.

**재생하면 도트가 찌글거린다면** `부드러운 도트 이동`(기본 켬)을 확인한다. 켜져 있으면 2D 퍼펫을 프리뷰에 보이는 배율 그대로
그리고 도트 칸 경계만 화면 1픽셀 폭으로 섞어서, 1픽셀 미만 움직임이 깜빡임(옛날 TV 노이즈) 대신 매끄럽게 보인다.
끄면 예전처럼 캔버스 크기로 그린 뒤 확대한다(비교용). 베이크 씬의 파트·장비 스프라이트에도 같은 셰이더가 붙는다.

파트를 눌러 격리해서 본 뒤에는 **◀ 전체 보기** 버튼이나 트리 맨 위의
`＊ 전체 합성` 행으로 돌아온다.

## 장비 붙이기

```gdscript
var item := DREquipItem.new()
item.slot     = "helmet"
item.part     = "Head"          # 리그 파트 이름
item.texture  = preload("res://equip/helmet.png")
item.offset   = Vector2(81, 2)  # 레스트 포즈 기준 이미지 좌상단 캔버스 좌표
item.z_index  = 30
$Puppet.equip(item)
```

- 같은 슬롯에 다시 `equip` 하면 교체된다.
- `follow_stretch = true`(기본)면 파트의 단축 보정을 같이 따른다.
  헬멧처럼 밀착된 것은 true, 매달린 것은 false.
- `tint_part(part, color)` 로 팔레트 스왑 흉내가 가능하다(가장 싼 배리에이션).

**장비 이미지를 3D 에서 구울 때**는 캐릭터와 **완전히 같은 카메라 / 같은 레스트 포즈**
여야 정렬된다. 그래서 `rig.json` 의 `view` 에 카메라 트랜스폼까지 통째로 저장해 둔다
(`DRBaker.apply_view()` 로 복원).

## 다른 리그 / 다른 종류

본 이름 매핑은 `core/part_profile.gd` 의 규칙 배열 하나다.
UE 마네킹(`upperarm_l`)과 Mixamo(`mixamorig:LeftArm`) 를 기본 지원한다.
차량·중장비는 규칙만 새로 쓰면 나머지 파이프라인은 그대로 돈다.

```gdscript
{"pattern": "(turret|포탑)", "part": "Turret", "sided": false}
```

`layer` 를 주면 움직임은 따로, 그리기 순서는 다른 파트 줄에 묶는다(발가락이 이 방식):

```gdscript
{"pattern": "(ball|toe)", "part": "Toe", "sided": true, "layer": "Foot"}
```

## 알려진 한계

- **스프라이트 단위 정렬은 픽셀 단위 깊이를 재현하지 못한다.**
  3D 에서는 z버퍼가 픽셀마다 판정하지만 2D 는 파트 한 장을 통째로 앞/뒤에 놓는다.
  어깨가 몸통을 감아 도는 곳처럼 **한 파트가 동시에 앞이기도 뒤이기도 한**
  경우에는 어떤 순서로도 완벽히 맞지 않는다. 실측
  (`tools/compare_cli.gd`, UAL1 192px, Idle 정지, 자동 순서, 2026-09-15 도트 셰이더 깊이 수정 후):

  | 시점 | 3D 렌더 대비 불일치 |
  |---|---|
  | 정측면 (yaw 90) | 9.4% |
  | yaw −45 | **3.9%** |
  | yaw −55 | 7.8% |
  | yaw −65 | 11.4% |

  **각도에 따라 2~3배 차이가 난다** — 이 모델·레스트 포즈에서는 −45° 가 가장 잘 맞았다. 단 레스트 정지 자세만 본 값이라,
  동작이 화면 안에서 일어나는지(걷기·공중제비는 측면이 유리)와 같이 보고 정할 것. 순서 문제는 순서로 푼다(관절 겹침 링으로는 안 고쳐짐).
  > 09-14 에 쟀던 "각도별 4.3~5.9%, 차이 작음"은 3D 렌더가 깊이를 안 쓰던 셰이더 버그(뒤쪽 면이 비침) 상태의 틀린 기준이었고,
  > 그 전의 12~22% 는 자세 드리프트까지 섞인 값이다. 불일치가 뭉치는 곳(3⁄4 사타구니, 정측면 몸통 뒤 팔 경계)도 09-14 기준이라 다시 확인이 필요하다.
- **깊이 회전은 표현 못 한다.** 컷아웃의 근본 한계. 파트가 카메라 쪽으로 돌면
  화면상 길이가 줄어드는데(단축), 이건 `stretch` 노드로 근사할 뿐이다.
  베이크 후 출력되는 `[단축률 진단]` 을 볼 것 — **1.00 에서 멀수록 그 파트는
  이 각도에서 위험**하고, 보통 레스트 포즈를 바꾸면 개선된다.
  측면 시점 기준 다리·몸통은 ±2%, 팔은 20~30% 나온다.
  **각도는 "동작이 화면 안에서 일어나는 방향"으로 고른다.** 예: `BackFlip`(뒤공중제비, 좌우축 회전)을
  yaw −38° 로 구우면 몸이 카메라 쪽으로 넘어와 몸통이 0.49배·머리 0.57배·손 0.16배까지 줄어
  **종이 한 장이 접히는 것처럼** 보인다. 같은 동작을 측면(yaw 90)으로 구우면 몸통·머리 1.00배 그대로
  엉덩이가 화면 안에서 398° 돈다(팔은 옆으로 뻗어 측면에서도 줄어듦). (2026-09-15 실측, 184px, 레스트 `Idle_LookAround`)
- **발가락은 접히지 않는다(기본).** 184px 에서 발가락은 2~4픽셀이라 따로 꺾으면 1픽셀도 안 되게 꿈틀거리기만 해서
  발에 합쳤다. 발은 레스트 모양 그대로 한 장, 발목에서 회전만 한다(늘이기 없음). 발끝이 접히는 모습이 꼭 필요하면 `--split_toes`.
- **도트를 확대해서 연속 재생하면 경계가 깜빡일 수 있다(옛날 TV 노이즈).** 60fps 로 매 프레임 1픽셀 미만씩 움직이면
  도트 칸이 통째로 켜졌다 꺼졌다 한다(이미 도트인 조각을 다시 돌리고 옮기며 한 번 더 뽑기 때문. 픽셀 스냅은 오히려 나빠짐).
  `부드러운 도트 이동`(기본 켬)이 칸 안쪽은 또렷하게 두고 칸 경계만 화면 1픽셀 폭으로 섞어서 줄인다 —
  Idle 실측 노이즈 25.5 → 4.9, 움직임 양은 그대로. 단 **게임이 캐릭터를 확대해서 그릴 때만** 효과가 있고
  (저해상도 화면에 1:1 로 그린 뒤 화면 전체를 키우면 효과 없음), 뛰기처럼 빠른 동작에서 남는 변화는 3D 렌더와 같은 수준이라 더 줄지 않는다.
- 캐릭터 키 96px 이하에서 **손가락 단위 파트는 무의미**하다(손이 2~3픽셀).
  기본 프로필이 손가락 20본을 `Hand` 하나로 접는 이유.
- 숨겨진 `Window` 안에서는 SubViewport 가 렌더되지 않는다. 창을 연 채로 베이크할 것.
- 아웃라인 패스, 팔레트 LUT, 장비 3D 베이크 모드는 아직 없다.
