> 사용법(버튼·조작)은 [`addons/dot_rigger/README.md`](../../addons/dot_rigger/README.md). 이 문서는 **왜 이렇게 만들었는지**를 남긴다.

## 1. 무엇을, 왜

### 출발점
처음 구상은 창 두 개였다.

- **A뷰** — 3D 모델을 불러와 X·Y·Z 각도를 정하고, 도트화 셰이더를 입혀 스프라이트를 뽑는다.
- **B뷰** — 뽑은 이미지를 손·발·관절 레이어로 나눈다(스파인과 비슷).

### 결론: 프레임 스프라이트가 아니라 **컷아웃 퍼펫**
목적이 "옷·무기·장구류를 갈아입는 캐릭터"라서, 프레임을 통째로 굽는 방식은 장비 종류만큼 이미지가 **곱으로** 늘어난다. 파트를 본에 붙이는 컷아웃이면 장비 1종 = 이미지 1장, **합으로** 늘어난다.

| 헬멧 1종 추가 시 필요한 이미지 | 장수 |
|---|---|
| 프레임 베이크 — 최초 가정 (8방향 × 애니 6 × 12프레임) | 576 |
| 프레임 베이크 — 확정 조건 (1방향 × 애니 6 × 12프레임) | 72 |
| **컷아웃 부착 (이 도구)** | **1** |

### 사용자가 확정한 조건

| 항목 | 결정 |
|---|---|
| 시점 | A뷰에서 정한 **각도 하나로 고정**. 게임은 그 각도만 보여준다 |
| 애니메이션 | **3D 애니메이션의 본 각도를 투영해 자동 생성**. 2D에서 손으로 키를 찍지 않는다 |
| 대상 | **휴머노이드 우선**. 탱크·중장비는 나중에(파트 프로필만 추가하면 됨) |
| 그리기 순서 | 자동(3D 깊이) 기본 + 수동 고정 순서. **사용자는 수동을 쓰는 중** |
| 발 | 발가락 뼈는 **발에 합치고**, 발은 레스트 모양 그대로 한 장·**발목에서 회전만**(늘이기 없음). 오전에 발가락을 따로 꺾었다가 2~4px 발가락이 꿈틀거려 어설퍼서 사용자가 이 방식을 정함 (09-15, 02 P6) |
| 시점 조작 | 숫자 입력칸이 기준. 3D 프리뷰의 **회전 기즈모**는 그 칸 값을 바꾸는 손잡이 (09-15) |

### B뷰는 따로 만들지 않았다
관절에서 자르는 위치(본 웨이트), 피벗(본 투영), 계층(본 부모 관계)이 **3D에서 전부 자동으로 확정**된다. 사람이 할 일은 **그리기 순서 지정과 검수**만 남아서, 별도 창 대신 A뷰 오른쪽 **"그리기 순서" 열**로 흡수했다.

## 2. 파이프라인

```
.glb  (스킨드 메쉬 1개 + Skeleton3D + AnimationPlayer)
  │
  ├─ part_profile   본 이름 → 파트 이름 (정규식 규칙, 좌우 접두/접미 정규화)
  ├─ mesh_splitter  정점마다 웨이트가 가장 큰 본 → 파트. 파트별 ArrayMesh 로 분해 (+관절 겹침 링)
  ├─ rig_model      파트 계층 · 루트 본(살 붙은 본만) · tail 점 · 3D→2D 투영 · 레이어(순서 목록 줄)
  ├─ baker          SubViewport + 직교 카메라 + 도트 셰이더. 파트를 한 장씩 단독 렌더
  ├─ exporter       parts/*.png + rig.json + puppet.tscn (Skeleton2D + AnimationPlayer)
  └─ runtime        DRPuppet.equip(DREquipItem) — 장비를 파트에 부착
```

## 4. 설계 결정과 이유

### 4-1. 파트는 노드 계층이 아니라 **본 웨이트**로 자른다
리깅된 캐릭터는 팔·손이 별도 메쉬가 아니다. UAL1도 메쉬는 `Mannequin` 하나, 본은 65개(그중 손가락이 40개). 노드 하이어라키로는 손·팔뚝을 나눌 수 없다. 정점마다 웨이트가 가장 큰 본(argmax)을 찾아 파트를 정한다 — 추측이 아니라 모델에 이미 들어 있는 데이터다.

### 4-2. 셰이더 마스킹 대신 **메쉬 자체를 파트별로 분해**
- 파트마다 `MeshInstance3D`가 따로 생겨 **에디터에서 눈으로 확인**할 수 있다.
- 관절 겹침(bleed)이 삼각형 배정 규칙만으로 공짜로 생긴다.
- 정점 배열은 원본을 그대로 공유하고 **인덱스 배열만** 파트별로 바꾼다(리맵 비용 없음).

### 4-3. 삼각형 배정과 **관절 겹침 링**
- 규칙: **"정점 하나라도 이 파트면 이 삼각형을 가져간다."** → 경계 삼각형이 양쪽에 다 들어가 구멍이 없다.
- `bleed_rings` 만큼 삼각형 한 겹씩 더 확장한다.
- **관절에서만 자란다.** 바깥 실루엣은 이웃 파트와 안 닿으니 안 자란다.
  실측 `L_Calf`: 가로 18px 고정, 세로 50 → 53 → 57px (링 0/1/2). 발목 겹침 픽셀 링0=15px, 링2=106px.
- **전체 공통 값**이다. 관절별로 따로 못 정한다.
- 목적: 2D에서 관절을 굽힐 때 이음새가 벌어지는 틈을 메운다. 대가: 넓을수록 이웃 살점을 들고 다녀서 순서가 어긋나면 경계에 턱이 보인다. 그리기 순서 문제는 이 값으로 못 고친다(yaw −45° 에서 링 1·링 0 모두 불일치 5.9% — 09-14, 3D 기준이 틀렸던 C9 수정 전 측정).

### 4-4. 파트는 **단독 렌더**한다 (3D 합성의 반대)
컷아웃은 팔을 돌리면 몸통에 가려졌던 부분이 드러나야 하므로, 파트 이미지는 **가려진 부분까지 온전해야** 한다. 나머지 파트를 숨기고 한 장씩 찍는다.

### 4-5. 루트 본 = 파트 안 최상위 본 **중 정점 웨이트가 있는 본**
UE·Mixamo 리그 맨 위의 `root` 는 웨이트도 없고 제자리 애니메이션에서 안 움직이는 **바닥 기준점**이다. 이걸 피벗으로 잡으면 힙 피벗이 발바닥에 찍히고 힙·상체가 고정된다(→ 버그 C3). 그래서 splitter 가 모은 `weighted_bones` 만 후보로 본다. 이름으로 거르지 않는 이유: 리그마다 기준점 본 이름이 다르다.

### 4-6. tail 점 — 리그 규격에 의존하지 않는 각도 계산
파트마다 "루트 본 공간에 고정된 점(`tail_local`)"을 하나 잡는다. 어떤 프레임이든 **head·tail 두 점만 카메라로 투영**하면 2D 각도 · 화면상 길이(단축률) · 깊이가 나온다. 본의 로컬 축 방향(리그마다 다름)을 몰라도 된다.

tail 위치 결정 순서:
1. 파트 말단 본들의 자식 중 **파트 밖으로 나가는 본**들의 레스트 위치 평균
2. 없으면 말단 본 자체 위치 평균 (말단이 루트 하나뿐이면 제외)
3. 그래도 없으면 부모→루트 방향으로 0.1 연장

### 4-7. 애니메이션은 **레스트 대비 델타 + 위치 트랙까지**
- Bone2D 레스트 회전은 0, 위치는 부모 기준. 애니 회전 = (현재 월드각 − 레스트 월드각) − 부모의 같은 값.
- **위치 트랙도 넣는다.** 3D 투영은 2D 강체 계층으로 딱 떨어지지 않아(단축 때문에) 회전만 넣으면 관절이 흘러간다. 위치를 투영값에 맞추면 정확히 일치한다.
- 각도는 `atan2` 경계에서 360° 튀므로 프레임 순서대로 펴고(unwrap), 루프 애니는 0프레임 사본을 끝에 붙여 이음새를 닫는다.
- 샘플은 `[0, length)`(루프) / `[0, length]`(비루프), 기본 12fps.
- 이 계산은 `DRRigModel.project_local()` 하나로 모았다 — **베이크와 2D 프리뷰가 같은 코드**를 쓴다. 호출은 `DRBaker.project_local()` 을 거친다(동작 평면화 여부 포함, → 4-20).

### 4-8. 단축 보정 (stretch)
팔이 카메라 쪽으로 돌면 화면상 길이가 짧아지는데 강체 스프라이트는 이걸 못 해서 관절이 떨어져 보인다. 측면 시점 실측: 다리·몸통·머리 0.99~1.02, **팔 0.69~1.05**.
노드 구조:
```
Bone2D(파트)            position / rotation 애니
 └ stretch (Node2D)     rotation = rest_angle,  scale = (s, 1) 애니   ← 본 축을 x 에 맞춰 x 만 늘림
    └ art (Sprite2D)    rotation = -rest_angle, position = R(-rest_angle)·(crop원점 − rest_head)
```
`s` 는 1/1.6 ~ 1.6 으로 제한. 끌 수 있다(끄면 도트 결은 깨끗하지만 팔 관절이 벌어질 수 있음).
파트별로도 끌 수 있다 — 프로필 규칙 `"stretch": false` → `rig.no_stretch` → `project_local()` 의 `s = 1`(프리뷰·베이크 공통, 늘이기 트랙 안 만듦). 기본 프로필은 **아무 파트도 끄지 않는다** — 09-15 에 발을 껐다가 되돌렸다: 레스트에서 카메라를 향해 짧게 찍힌 발이 걸을 때 못 길어져 3D 와 더 벌어졌다(02 P8). 발가락 분리 모드의 Toe 만 끈다.
파트별 **제한**도 있다(09-16): `"stretch_limit": 1.15` → `rig.stretch_limit` → `project_local()` 에서 `s` 를 1/1.15~1.15 로 묶는다. 기본은 **발**만 — 팔다리처럼 1.6배까지 두면 50px 발이 걸음마다 부풀어 "지렁이"처럼 보였다(사용자 표현). 3D 실루엣과는 몇 px 더 벌어지지만 2D 게임 발은 원래 안 늘어난다.
**각도 안정화** `"angle_fade": 0.45` → `rig.angle_fade`: 손·발처럼 짧은 끝 파트가 카메라를 향해 단축률이 문턱 아래로 떨어지면 2D 각도가 잡음처럼 튄다 → 부모 기준 회전을 단축률에 비례해 레스트(0) 쪽으로 누른다(`_fade_rot`, 단축률은 `_fore_of` = 화면 길이 ÷ 실제 뼈 길이). 평면화 모드에서는 포즈 시점의 단축률로 같은 처리. 측면·3⁄4 처럼 단축률이 0.45 이상이면 아무 영향 없다. 검사: `layer_check` [0] — 정면(yaw 0) Jog_Fwd 에서 L_Foot 회전 폭이 켬 < 끔의 80%.

### 4-9. 그리기 순서 (z)
- 깊이 = **head~tail 평균**의 카메라 공간 z. 긴 파트(전완·허벅지)는 루트 본 한 점의 깊이가 파트 전체를 대표하지 못한다.
- 정렬 단위는 **레이어**(그리기 순서 목록의 한 줄)이고, 레이어 순서를 파트로 펼쳐 z 를 매긴다. 발가락은 발 레이어라 항상 발 바로 위(→ 4-15).
- 내림차순 정렬 = 먼 것부터 = 먼저 그림.
- **자동**: 프레임마다 z 트랙(`UPDATE_DISCRETE` + `INTERPOLATION_NEAREST`). **수동**(`z_override`): 순서를 모든 프레임에 고정하고 z 트랙을 만들지 않는다.
- 애니를 안 틀어도 맞도록 **정지 상태 z_index 도 씬에 박는다**.
- Sprite2D 는 `z_as_relative = false` (Bone2D 가 중첩돼 있어 상대값이면 누적됨).

### 4-10. 자세 고정은 `speed_scale = 0` — `pause()` 금지
`set_pose()` = `play()` → `seek(t, true)` → `advance(0)`. AnimationPlayer 는 setup 에서 `speed_scale = 0` 으로 세워 둔다.
- 재생 중이면 파트 15장을 찍는 사이 자세가 흐른다(→ C1).
- `pause()` 는 믹서가 자세 적용을 멈춰 **바인드 포즈로 돌아간다**(→ C2).
- 프리뷰 재생은 `set_playback(true)` 로 speed_scale 만 1로. 베이크는 항상 `set_pose()` 를 거치므로 영향 없음.

### 4-11. 프리뷰 두 모드
| 모드 | 방식 | 순서 반영 | 재생 |
|---|---|---|---|
| 3D (기본) | 파트 메쉬를 3D 로 렌더, z버퍼가 픽셀마다 판정 = **정답** (단 09-15 셰이더 수정 전에는 깊이를 안 써서 틀렸음 → 02 C9) | ✗ | 엔진이 직접(speed_scale 1) |
| **2D 순서** | 파트 이미지 캐시 + **베이크 씬과 같은 노드 구조 퍼펫**을 `project_local()` 로 움직임 = **베이크 결과 미리보기** | ✓ | `_process` 에서 투영 |

- 2D 캐시는 캔버스 전체 크기 이미지(크롭 안 함)라 레스트에선 (0,0) 에 놓으면 맞는다.
- 캐시 키 `_render_sig()` = 시점 값 + 겹침 링 + 명암 단계 + 앰비언트 + 알파 + 색 양자화.
- `_process` 는 `_busy` 동안 자세를 절대 안 건드린다(→ P3).
- `부드러운 도트 이동` 이 켜져 있으면 퍼펫 뷰포트를 화면 배율로 키워 그린다(→ 4-17).
- 퍼펫 뷰포트는 캔버스보다 `PUPPET_PAD`(25%, 각 변) 넓다(`_puppet_pad()`, 루트 Node2D 를 여유 폭만큼 안쪽에). 구운 퍼펫에는 틀이 없으므로 엎드리기·쭈그리기가 레스트 틀 밖으로 나가도 프리뷰에서 잘리지 않게(09-16 사용자 지적). `_canvas_box` 가 베이크 캔버스 틀을 선으로 그린다. `_pv_logical` 은 여유 폭 포함 크기. 3D 모드는 베이크 뷰포트 그대로.
- 재생 속도(`_speed`: ×1·½·¼·⅒·멈춤)와 스크럽(`_scrub`). 3D 는 `AnimationPlayer.speed_scale`(`set_playback(on, speed)`), 2D 는 `_process` 의 `delta × 배속`. 재생 중엔 두 모드 다 `_process` 가 돌아 3D 는 `current_animation_position` 을 읽어 슬라이더만 맞춘다. 슬라이더를 끌면 `set_pose(재생 애니, t)`(멈춤이면 그 프레임에 고정). 스모크 25.
- **재생할 애니는 레스트 포즈와 따로** 고른다(▶ 재생 옆 드롭다운 = 5번에서 고른 동작, 없으면 레스트 애니). `_render_preview_once` 는 늘 레스트 포즈로 기준값·파트 캐시를 잡은 뒤, 3D 재생이면 `set_pose(재생 애니, 0)` 후 speed_scale 1, 2D 재생이면 `_process` 가 `_current_play_anim()` 으로 자세를 세운다. 예전엔 레스트 애니를 돌려서, 수영을 보려고 레스트를 바꾸면 파트 그림까지 수영 자세로 찍혔다.

### 4-12. 창과 캐시
- 창 X = `hide()` 만. 불러온 모델·설정 유지가 목적. 코드 수정 후엔 `창 새로 만들기(초기화)` 메뉴.
- 왼쪽 열(09-16): 섹션 0~6 은 `FoldableContainer`(Godot 4.5+) 로 접힌다 — `_section(col, 제목, folded)` 가 만들고 `_sections` 에 기억, `_fold(접두, bool)`. 도트화·파트 분리는 접힌 채 시작하고 모델은 불러오면 접는다. **7. 출력(폴더·기존 애니 유지·베이크·진행바)은 스크롤 밖 바닥**이라 늘 보인다. 이유: 섹션이 늘어 스크롤이 길어지고 베이크 버튼이 맨 아래라 작업 때마다 내려야 했음. 스모크 1-2·2·16(베이크 버튼 배치).
- `_fit_sig` — 시점 값이 바뀔 때만 카메라 재설정·자동 맞춤(렌더 3번짜리라 클릭마다 하면 느림).
- `_dirty` — 갱신 중 들어온 요청을 버리지 않고 끝나고 한 번 더.
- `_fill_z_list()` — 순서가 그대로면 목록을 안 건드림(clear 하면 다중 선택이 날아감). 바뀌면 **이름으로** 선택 복원.
- `_iso_parts` — 드롭다운·파트 트리·그리기 순서 목록이 공유하는 "프리뷰 대상 파트 집합"(빈 집합 = 전체).
- 창 전체 `auto_translate_mode = DISABLED` — 에디터가 "Idle" 을 "대기" 로 번역해 보여줬음.
- 툴팁은 `_tip(control, text)` 로 붙인다 — 같은 줄(HBoxContainer)의 이름표 Label 에도 같은 툴팁을 넣고 `mouse_filter = PASS` 로 바꾼다. Label 기본값은 마우스 무시라 그냥 두면 **글자 위에서는 툴팁이 안 뜬다**(09-15 사용자 지적). 스모크 1-1 번이 검사.
- 5번 동작 선택의 기준은 `_picked_anims`(이름 집합)다. 검색으로 목록을 다시 채워도 복원되고, 베이크·프리셋도 이 집합을 읽는다. 목록(ItemList) 선택만 읽던 때는 검색을 바꾸면 선택이 풀려 마지막 검색에서 고른 것만 구워졌다(02 P7). 스모크 7-1 번이 검사.
- 파일 대화상자는 **툴 창의 자식**으로 붙인다(에디터 본체에 붙이면 툴 창이 뒤로 밀림). `EditorFileDialog` 가 null 이면(에디터 밖) `FileDialog` 로.

### 4-15. 파트와 레이어 (09-15)
- **파트** = 애니메이션 단위. 본에 붙어 따로 움직인다.
- **레이어** = 그리기 순서 목록의 한 줄. 깊이를 함께 다룬다.
- 대부분 파트 하나 = 레이어 하나. **기본 프로필은 발가락을 발에 합쳐 파트 = 레이어 15개**다(→ 02 P6). 레이어를 따로 쓰는 건 **발가락 분리 모드**(`humanoid(true)` / `bake_cli --split_toes`) — 발가락은 "움직임은 따로, 순서는 발과 한 몸"이라 파트는 나누고 레이어는 발에 묶는다.
  - 프로필 규칙에 `"layer": "Foot"` 한 줄 → `L_Toe` 의 레이어는 `L_Foot`.
  - 한 레이어 안은 계층 순(부모가 뒤) → 발가락은 **항상 발 바로 위**. 발 줄을 옮기면 발가락이 따라간다.
  - 목록에서 발 줄을 고르면 프리뷰에 발 + 발가락이 같이 뜬다. 드롭다운에서는 발가락만 따로 격리해 볼 수 있다. 파트 트리에는 `L_Toe (L_Foot 줄에 묶임)` 으로 표시.
- 순서를 쓰는 곳은 전부 **레이어 순서 → `expand_layers()` → 파트 순서**를 거친다: 창 목록 · 2D 퍼펫 · 자동 z(`project_local`) · 베이크 z_index · rig.json · 비교 도구.
- 옛 프리셋이나 파트 이름이 섞인 목록은 `normalize_layer_order()` 가 소속 레이어로 바꿔 받는다(사용자 프리셋 15줄 그대로 호환).
- 왜 발가락만: 조사해 보니 UAL1 `ball_l` 이 정점 27개를 지배하고(발 78개), 120개 애니 중 69개에서 접힌다(기어가기 최대 71.6°, `Jog_Fwd` 38.3°). 손가락은 도트 해상도에서 2~3픽셀이라 여전히 손 하나로 둔다. 단 실제로 따로 꺾어 보니 발가락도 184px 에서 2~4픽셀이라 꿈틀거리기만 해서, 같은 날 기본을 "발에 합침"으로 바꿨다.
- 검사: `tools/layer_check_cli.gd` ([0] 기본 = 발에 합침 · [1]~[4] 분리 모드: 구성 → 자동 z → 수동 순서 → 구운 씬·rig.json)

### 4-16. 시점 조작 — 입력칸이 기준, 기즈모는 손잡이 (09-15)
- 값의 원본은 `2. 시점` 의 Yaw·Pitch 칸 **하나뿐**. 기즈모는 그 칸을 바꾸고, 칸이 바뀌면 기즈모가 다시 그려진다. 그래서 기즈모로 돌린 각도가 그대로 프리셋·베이크·rig.json 카메라에 들어간다.
- 드래그 중에는 칸 숫자(`set_value_no_signal`)와 카메라(`DRBaker.orbit_camera()`)만 바꾸고, 손을 뗄 때 한 번 전체 갱신(자동 맞춤·그리기 순서). 매 픽셀 전체 갱신은 렌더 3번짜리라 끊긴다.
- 칸이 1° 단위라 드래그 누적값을 따로 들고 있다가 정수로 넣는다 — 칸 값·카메라·베이크 각도가 항상 같게.
- `orbit_camera()` 는 자동 맞춤이 옮겨 둔 카메라의 오른쪽/위 오프셋을 떼어 새 각도에 다시 얹어, 돌리는 동안 인물이 화면에서 튀지 않는다.
- 축 끝 클릭 = 그 방향에서 보기(+Z → Yaw 0, +X → Yaw 90, +Y → Pitch 89). 기즈모 그림은 카메라 기저를 그대로 투영하므로 화면과 항상 일치.
- **Pitch 양수 = 위에서 내려다봄.** `DRBaker.view_basis()` 가 `Basis.from_euler` 의 X 부호를 뒤집는다(→ 02 C8).
- 3D 모드에서만 보인다(2D 순서 모드는 캐시 이미지라 시점을 바꾸면 다시 찍어야 함).
- `Ortho 크기` = 직교 카메라가 화면 세로로 담는 실제 높이(모델 단위). 작을수록 인물이 크게 찍힘. 0 = 모델 크기 × 1.15 자동. `자동 맞춤` 이 켜져 있으면 시작값일 뿐 결국 화면에 꽉 차게 다시 잡힌다. UAL1 은 192px·여백 6·자동 맞춤에서 약 1.91. 프리뷰 휠 확대와 달리 **베이크 결과가 바뀐다**.
- `캐릭터 이동 X/Y`(px, +X 오른쪽 · +Y 위) = `Options.view_offset`. `apply_camera()` 가 카메라를 `-offset × (Ortho / 세로 픽셀)` 만큼 자기 오른쪽/위 방향으로 옮긴다 → 도트 크기는 그대로 틀만 이동. 자동 맞춤은 이후 다시 가운데로 맞추므로 사실상 자동 맞춤 끔일 때 쓰는 값. `_view_sig` 에 들어가 값이 바뀌면 카메라를 다시 잡고, `serialize_view()` 에 `view_offset` 으로 남는다(애니 이어 담기 판정은 실제 `camera_origin` 으로 함). 이유: 자동 맞춤 끔·Ortho 0 은 **서 있는 기본 자세 상자 중심**을 겨누는데, UAL1 애니 120개 중 20개(Swim·Death·BackFlip·Crawl 계열)가 뼈 기준으로 그 틀을 벗어났다(`Swim_Fwd` 는 몸이 중심보다 0.9~1.45m 아래).

### 4-27. 장비(무기) 툴 — 두 번째 창 (09-21 설계·런타임, 09-22 창 · 앞 조각 · 기즈모)
- **사용자 요구**: 무기 3D 모델을 불러 매핑·파트별 관리(숨기기·위치 조정) → 퍼펫과 같은 시점으로 2D 평면화 → **조준하는 손에 피벗** → 퍼펫의 그리기 순서 목록에 무기를 끼워 넣어 몇 번째에 그릴지 정함 → 프리뷰. 동기 = 리소스 관리(무기를 늘릴 때마다 손으로 맞추지 않게). 무기 교체 있음 · 무기 안의 움직임(노리쇠 등) 있음 — 둘 다 사용자가 확인.
- **합의한 구조**: 기존 창과 별개의 `Dot Rigger — 장비 굽기` 창. ① 모델(파트 보이기/숨기기·위치) ② 잡는 법(붙일 파트 = 기본 `R_Hand`, 3D 병사의 레스트 손 위에서 그립 맞춤) ③ 그리기 순서(세트의 `layer_order` 에 무기 줄을 끼움) ④ 미리보기(실제 구운 2D 퍼펫에 장착해 재생·조준) ⑤ 굽기(`sets.json` 의 모든 세트를 한 번에).
- **피벗은 세트마다 손으로 잡지 않는다**(사용자는 그럴 줄 알았음): 그립을 3D 에서 **한 번** 정하면(손 뼈 기준 변환) 세트마다 그 세트의 레스트 자세로 무기를 손에 붙여 같은 카메라로 찍으므로 그림·오프셋이 세트별로 자동으로 나온다. 세트별로는 미리보기를 보며 미세 조정만. 무기 교체를 위해 그립은 "손 쪽 소켓(캐릭터당 1번) × 무기 쪽 그립 점(무기당 1번)"으로 나눌 것 — 무기 N개에 조정 N번이지 N×세트 번이 아니다.
- **발판(이미 있던 것)**: `rig.json` 의 `view`(카메라 basis·origin·ortho_size·size·rest_anim/time·planar — `DRBaker.apply_view()` 로 그대로 복원) · `layer_order` · `composites`(레스트가 합성 동작인 세트를 다시 만들 때) · `DREquipItem` + `DRPuppet.equip()`.

### 4-26. 런타임 `DRPuppetSet` — 세트 여러 벌을 캐릭터 하나처럼 + 마우스 조준 (09-21)

- `runtime/dr_puppet_set.gd`(@tool, Node2D): `sets.json` 을 읽어 세트의 `puppet.tscn` 을 **전부 자식으로** 들고(안 보이게), `play("이름")` 이 그 동작이 든 세트를 보이게 하고 재생한다 → 게임 코드는 폴더를 모른다. 미리 다 올려 두므로 세트를 바꿀 때 끊김이 없다(09-17 구조 토론의 "리그를 다 넣어 두고 보이기만 바꾼다").

- **조준**: 애니메이션 위에 `aim_part`(기본 Torso) 본의 회전에 각도를 **더한다** — 머리·팔·(손에 붙인)총이 몸통의 자식이라 한 덩어리로 돌아 왼손이 총에서 안 미끄러진다(09-17 토론). AnimationPlayer 가 그 속성을 매 프레임 덮어쓰므로 **`callback_mode_process = MANUAL`** 로 바꾸고 `_process` 에서 ① 지난 프레임에 더한 각도를 빼고 ② `advance(delta)` ③ 새 각도를 더한다. 이 순서가 아니면 애니가 끝났거나 멈춘 동안 각도가 매 프레임 쌓인다(검사: 멈춘 애니 위 300프레임 — 변화 0).
  - 각도 = holder(= 반전까지 적용된 퍼펫 좌표)에서 잰 `atan2(dy, dx × 구운 방향)` 을 `±aim_limit_deg` 로 자르고, `lerp_angle` + `1 − exp(−Δt × aim_speed)` 로 따라간다. 위 = −(반시계).

### 4-25. 선의 색 방식 — 카툰 / 픽셀 퍼펙트, 둘 중 하나 (09-21)
- ⚠ **용어**: 사용자가 말하는 "픽셀 퍼펙트" = **가장자리 도트가 그 자리 몸 색의 톤에 맞춰 어둡게 들어가는 1도트 선**(3D → 도트 셰이더 쪽의 "pixel perfect outline", 도트 그림의 selout). 처음엔 이 말을 "도트 격자에 맞춰 그리기"로 알아듣고 4-24 를 만들었다 → 그 기능은 `도트 격자 고정` 으로 이름을 바꾸고(내부 `pixel_grid`) 이 말은 선 색 방식에 쓴다(02 M4).
- 카툰(한 색으로 두르는 선)과는 성격이 달라 **같이 적용될 수 없으므로 토글**(사용자 요청): 상단 바의 `카툰` · `픽셀 퍼펙트` 체크박스가 같은 `ButtonGroup` — 하나를 켜면 다른 하나가 꺼진다. 색 버튼은 카툰일 때만, `%` 칸(어둡게 하는 정도)은 픽셀 퍼펙트일 때만 풀린다. 두께 칸(0 = 선 없음)과 `전체 실루엣`/파트별은 두 방식 공통.
- 구현은 같은 셰이더(`smooth_pixel.gdshader`)의 uniform 둘: `outline_tone`(bool) · `outline_tone_strength`(0~1). 선의 한 도트 색 = `line_texel()`:
  - 카툰: `outline_color`.
  - 픽셀 퍼펙트: `nearest_opaque()` — 그 도트에서 맨해튼 거리 `outline_px` 안의 **가장 가까운** 불투명 텍셀 색(같은 거리면 평균) × (1 − strength). 밑깔개(전체 실루엣)와 파트별 선 모두 같은 함수를 쓴다. 밑깔개는 파트마다 **자기 텍스처**에서 색을 가져오므로 주황 살 옆은 짙은 주황, 보라 관절 옆은 짙은 보라가 된다.
  - 거리가 맨해튼(상하좌우)이라 대각선으로 꺾이는 곳에 도트가 겹쳐 쌓이지 않는다 — 1도트 선이 1도트로 유지(도트 그림에서 말하는 pixel-perfect line).
- 익스포터 `outline_style`(`OUTLINE_CARTOON` 0 / `OUTLINE_PIXEL_PERFECT` 1) · `outline_tone`, cfg·프리셋 같은 키(`@export_enum`), `rig.json` `outline_style` "cartoon"/"pixel_perfect" · `outline_tone`, CLI `--outline_style=pixel_perfect --outline_tone=0.45`. 장비 밑깔개는 본체 밑깔개의 머티리얼을 그대로 쓰므로 장비 그림의 색에서 톤을 가져온다.
- 실측(스모크 34, 정측면 · Idle 레스트 · 선 1도트 · 경계 섞기 끔): 선 도트 875개 — 카툰은 전부 검정, 픽셀 퍼펙트는 검정 0 · **옆 몸 도트 × 0.55 와 98% 일치**(나머지는 같은 거리의 두 색을 평균한 모서리) · 캐릭터 안쪽 바뀐 픽셀 0.
- 검사: 스모크 34(토글 배타 · uniform · 선 색 · 베이크 설정·프리셋 왕복) · `sets_check`(픽셀 퍼펙트로 구운 씬의 uniform · rig.json, 기본 굽기는 카툰).
- 아직 안 한 것: 몸 **안쪽** 경계(팔이 몸통 앞을 지나는 곳)의 톤 선 · 볼록한 모서리의 밝은 선(3D 도트 셰이더들이 같이 쓰는 것). 파트별 모드(`전체 실루엣` 끔) + 픽셀 퍼펙트가 안쪽 경계 선에 가장 가깝다.

### 4-24. 도트 격자 고정 — 도트 해상도로 그린 뒤 통째로 확대 (09-21)
- 이름: 처음엔 이 기능을 "픽셀 퍼펙트"라 불렀으나 사용자가 뜻한 것은 4-25 였다 → `도트 격자 고정`(내부 `pixel_grid`, CLI `--pixel_grid`). 산출물 이름(`puppet_pixel.tscn` · `DRPixelPuppet`)은 그대로.
- 문제: 컷아웃 퍼펫을 게임에서 그냥 확대하면(scale 3) 파트가 돌 때 텍셀이 **기울어진 큰 사각형**으로 보인다 — 도트 크기·격자가 제각각. 실측(96px · Jog_Fwd · 3배): 내용 있는 3×3 칸 1,703개 중 **1,106개**가 한 색이 아님.
- 해결: 퍼펫을 **배율 1 의 작은 SubViewport** 에 그리고 그 그림을 nearest 로 정수 배 확대 → 돌아간 파트도 도트 격자에 다시 찍힌다(같은 조건에서 섞인 칸 **0 / 16,811**). `snap_2d_transforms_to_pixel` 로 위치도 정수 픽셀.
- 대가: 1픽셀 미만의 움직임이 사라져 느린 동작에서 도트가 톡톡 튄다(02 P5 의 "TV 노이즈" 와 같은 뿌리) — `부드러운 도트 이동` 과 **반대 성격**이라 같이 못 쓴다. 도트 격자 고정이면 경계 섞기를 끈다(1배에서는 흐려질 뿐). 기본값은 끔.
- 베이크: `DRExporter.pixel_grid`(cfg `pixel_grid`, 프리셋 `pixel_grid`, CLI `--pixel_grid`) → `_save_scenes()` 가 `puppet.tscn` 뒤에 **`puppet_pixel.tscn`** 을 만든다. 끄고 다시 구우면 예전 래퍼를 지운다(낡은 범위가 남지 않게).
  - 구조: 루트 `DRPixelPuppet`(`runtime/dr_pixel_puppet.gd`, @tool) → `View`(SubViewport: 투명 · nearest · snap · 3D 끔 · UPDATE_ALWAYS) 안에 `puppet.tscn` **인스턴스**(`Puppet`) + `Screen`(Sprite2D). ViewportTexture 는 씬에 저장하지 않고 `_ready` 에서 `view.get_texture()` 로 건다(저장된 ViewportTexture 의 경로·local-to-scene 문제를 피함).
  - 인스턴스로 남기려면 `owner` 를 **세 노드(View · Puppet · Screen)에만** 준다. 재귀로 다 주면 puppet.tscn 의 노드가 래퍼 씬에 통째로 풀려 저장된다(`pixel_check` 가 `.tscn` 글자에서 `instance=ExtResource` 있음 · `Bone2D` 없음으로 확인).
  - **뷰포트 크기 = 움직임 범위**: `pixel_bounds()` 가 레스트 + 구운 모든 애니의 모든 프레임에서 파트 그림 네 귀가 닿는 범위를 잰다(씬 조립과 같은 식: 본 = 부모 × T(p)R(r), 그림 = R(레스트각)·S(s,1)·R(−레스트각)·(캔버스 점 − 레스트 머리)) + `PIXEL_PAD` 2. 캔버스 밖으로 나가는 구르기·엎드리기도 안 잘린다. `rig.json` `pixel_view {size, origin}`.
  - 래퍼의 원점 = 퍼펫 원점(캔버스 왼쪽 위): `Screen.position = −view_origin × pixel_scale`. `extra_margin` 을 키워도 화면의 자리는 그대로(검사 [4]).
  - `pixel_scale`(정수)로 키운다 — 노드 `scale` 을 비정수로 주면 도트 크기가 들쭉날쭉.
- 창: 상단 바 `도트 격자 고정` → `_apply_puppet_scale()` 가 2D 퍼펫 뷰포트 배율을 1 로 고정 + snap, `_apply_part_material()` 이 `smooth_edges` 를 끔, `부드러운 도트 이동` 칸 잠금.
- 상단 바는 **HFlowContainer** — 체크박스 하나를 더 넣자 가운데 열 최소 너비가 커져 오른쪽 열이 또 창 밖으로 밀렸다(스모크 16, 02 U8 세 번째). 흐름 컨테이너는 항목이 늘어도 최소 너비가 안 커지고 다음 줄로 넘어간다.
- 게임 전체가 저해상도 뷰포트(스트레치 모드 viewport)면 래퍼가 필요 없다 — `puppet.tscn` 을 배율 1 로.
- 검사: `pixel_check_cli`(구조 · 3×3 칸 격자 · 범위 · extra_margin · 끄면 삭제) · 스모크 32.

### 4-23. 상하체 합성 — 하체 애니 + 상체 애니 = 새 동작 (09-21)
- 배경: 09-17~18 구조 토론의 "상하체 분리". 라이브러리에 "앉아 걸으며 조준" 같은 전신 동작은 없다. 그때는 게임 쪽 AnimationTree(Blend2 + 필터)를 말했는데, 사용자가 **도구에서 합성해 세트에 넣는** 쪽을 요청 — 게임은 그냥 `play("Crouch_Aim_Walk")` 하면 된다(대신 조합 수만큼 구운 애니가 늘어난다).
- **3D 뼈 트랙 단계에서 합성**한다(`DRBaker.build_composites`): 상체 파트(기본 `DEFAULT_UPPER_PARTS` = 몸통·머리·두 팔)의 뼈 트랙은 upper 애니에서, 나머지(힙·다리·파트에 안 속한 root)는 lower 애니에서 가져와 새 `Animation` 을 만들어 베이커의 자기 라이브러리(4-22 의 얕은 사본)에 넣는다. 2D 로 섞지 않는 이유: 단축률·늘이기·깊이(z)가 실제 3D 자세에서 계산돼야 팔이 몸통에 제대로 붙고 그리기 순서도 맞는다. 몸통 뼈는 힙의 자식이라 하체의 들썩임·기울기를 그대로 따라간다.
- 만든 동작은 **그냥 애니**다 — 5번 목록(하늘색 + 툴팁), 레스트 자동, 세트, 베이크, 평면화가 전부 그대로 돈다. 익스포터는 구운 것 중 합성인 것의 정의를 `rig.json` `composites` 에 남긴다.
- 길이가 다른 두 애니를 한 시간축에: 키를 복사하지 않고 `COMPOSITE_FPS` 30 으로 다시 샘플(`*_track_interpolate`). 각 출처는 전체 길이 동안 **정수 번** 돈다(늘이거나 줄여서 정확히 맞춤 → 반복 지점이 이어진다).
  - 네 값 = 질문 둘의 조합 — **누구의 시간에 맞추나(하체/상체) × 하체를 몇 번 돌리나(반복/1번)**. 팝업 글자(`LEN_ITEMS`)는 09-21 에 사용자와 같이 정했다:
    - `LEN_LOWER_SPEED`(0, 기본) `하체 시간에 상체를 맞춤 (하체 반복)`: 길이 = 하체 주기 × n(n = 상체 길이에 가장 가까운 정수배), 상체 1번 → 걸음 속도 유지.
    - `LEN_ONCE`(1) `하체 시간에 상체를 맞춤 (하체 1번)`: 길이 = 하체 길이, 둘 다 1번 → 상체가 그 안에 들어가도록 빨라지거나 느려진다.
    - `LEN_UPPER_SPEED`(2) `상체 시간에 하체를 맞춤 (하체 반복)`: 길이 = 상체 길이, 하체 n번 → 사격·장전 속도 유지.
    - `LEN_ONCE_UPPER`(3) `상체 시간에 하체를 맞춤 (하체 1번)`: 길이 = 상체 길이, 둘 다 1번 → 하체 한 주기가 그 길이로 늘어나거나 줄어든다.
  - `하체 1번` 의 쓸모 = 둘 다 한 번 하고 끝나는 동작(앉기 + 장전 등)을 같이 시작해 같이 끝내기. 걷기처럼 반복되는 하체에 쓰면 조준이 빨리 감기거나 걸음이 슬로모션이 된다. 상체가 하체보다 짧으면 0 과 1 의 결과가 같다(n = 1).
  - 이름의 이력(교훈): 처음 `하체 속도 유지 / 한 번씩 / 상체 속도 유지` → 사용자 "상체에 맞춤은 없어?"(있었는데 안 읽힘) → `하체 기준 / 상체 기준 / 하체 길이에 한 번씩 / 상체 길이에 한 번씩` → 사용자 "한 번씩이 도대체 무슨 뜻인지 모르겠다" → 사용자가 자기 말로 풀어 준 "하체의 초에 상체를 맞춘다" 를 그대로 이름으로. **옵션 이름은 내부 동작(속도 유지·기준)이 아니라 사용자가 말로 설명할 때 쓰는 문장으로 지을 것.** 값(0~3)은 프리셋에 저장되므로 바꾸지 않는다.
- **상체 방향 유지 `upper_keep`(0~1) · 몸통 각도 보정 `upper_pitch`(도)** (09-21, 합성 정의마다): 뼈의 회전은 부모 기준이라 하체 애니가 골반을 숙이면 상체 애니의 허리 각도를 그대로 얹어도 몸통이 그만큼 같이 숙는다(02 M5). `_fix_upper_roots()` 가 **상체의 뿌리 뼈**(부모가 하체인 상체 뼈 — 기본 구성이면 허리 첫 마디 하나, 팔만 상체면 두 위팔)의 회전 트랙을 다시 찍는다:
  - keep: `l = slerp(상체 애니의 부모 기준 회전, (합성에서 부모의 뼈대 기준 회전)⁻¹ × (상체 애니에서 이 뼈의 뼈대 기준 회전), keep)` — 1 이면 몸통이 세상 기준으로 상체 애니와 같은 쪽을 본다(언리얼의 Mesh Space Rotation Blend 와 같은 생각). 뼈대 기준 회전은 `_chain_rot()` 이 뿌리부터 부모 기준 회전(트랙이 없으면 레스트)을 차례로 곱해 구한다 — 하체·상체의 시각은 각자의 `_src_time()`.
  - pitch: 그 위에 `l = g_par⁻¹ × R(좌우 축, −pitch) × g_par × l` — + = 뒤로 젖힘. 좌우 축은 세상의 X 를 뼈대 공간으로 옮긴 것(`_side_axis_in_skeleton()`, setup 중에는 트리에 없어서 부모의 transform 을 직접 곱한다).
  - 값이 0 · 0 이면 아무것도 안 한다(예전 동작 그대로). 새로 `추가` 한 합성은 keep 1.0, 칸이 없던 예전 정의는 0 으로 열린다. `composite_info`·rig.json 에 두 값이 남는다. CLI `--composite_keep` · `--composite_pitch`.
  - 실측(Crouch_Idle + Idle, 몸통 숙임 = 힙 → 목 방향이 수직에서 앞으로 기운 각도): Idle 7.4° · 원본 Crouch_Idle 49.2° · keep 0% 30.2° · 50% 21.6° · **100% 12.8°**(가슴의 회전은 Idle 과 0.04° 차이 — 남는 5° 는 골반 → 허리 첫 마디 구간이 골반과 같이 기우는 몫) · 100% + 보정 +20° → −2.8°.
  - 팝업: `방향 유지` 슬라이더(5% 단위) + `각도 보정` 칸(±60°). 끄는 동안 값이 연달아 바뀌므로 프리뷰는 `_pv_dirty` 로 프레임당 한 번만 다시 만든다.
- **팝업 안 프리뷰**(09-21 사용자 요청 "합체된 결과물이 팝업에 떠 있고 여기서도 재생"): `DRBaker.make_composite_preview(def, upper_parts)` 가 고른 정의 하나를 합성해 **숨은 이름** `PREVIEW_ANIM`(`__composite_preview__`)으로 라이브러리에 넣는다 — `composite_anims` 에는 안 들어가고, 창의 `_read_anim_names()` 는 `__` 로 시작하는 이름을 건너뛴다(목록·세트·베이크에 안 나옴). 팝업은 베이커의 3D 뷰포트 텍스처를 TextureRect 에 그대로 걸고 `_process` 에서 `set_pose(PREVIEW_ANIM, t)` 로 돌린다(▶ · 속도 · 슬라이더). 하체·상체 동작·길이 맞춤·반복·상체 파트가 바뀌면 다시 만들고, 이름만 바뀌면 안 만든다. 닫히면(`visibility_changed`) `clear_composite_preview()` + `closed` 신호 → 창이 `_refresh_preview()` 로 자기 자세·파트 표시를 되돌린다. **같은 베이커의 자세를 둘이 바꾸면 안 되므로** 팝업을 열 때 창의 재생을 끄고 렌더(`_busy`)가 끝나길 기다린다.
- 안전장치: 없는 동작 · 같은 합성 이름 · **모델에 이미 있는 애니 이름**이면 만들지 않고 `composite_warnings`. 정의를 바꿔 다시 부르면 예전 합성은 라이브러리에서 뺀다. 합성으로 만든 동작은 재료 목록에서 뺀다(합성의 합성 금지). 이름이 비면 `하체+상체`.

### 4-20. 동작 평면화 — "페이퍼맨" 느낌을 없애는 2D 게임식 동작 (09-16)
- 문제: 3D 애니를 게임 시점(3⁄4)으로 그대로 투영하면 팔이 카메라 쪽으로 오갈 때 `s` 가 0.5~1.6 으로 변하고 각도도 깊이 방향으로 돌아, 사용자 표현으로 "오른손이 z축으로 확 오는" 종이 접힘. 2D 게임 컷아웃은 팔다리가 **화면 안에서만** 돈다.
- 방법: **각도는 포즈 카메라에서, 그림은 렌더 카메라에서.** `DRBaker.pose_camera`(렌더 안 함, `current = false`)를 `effective_pose_yaw()`(자동 = 렌더 yaw 에 가까운 ±90, pitch 0), 렌더 카메라와 같은 크기·거리로 둔다(`_sync_pose_camera()` — `_place_camera`·`auto_fit`·`apply_view` 끝에서). `capture_rest(…, pose_cam)` 이 포즈 시점 레스트 각도·머리 위치(`rest_angle_pose`·`rest_head_pose`)를 저장하고, `project_local(…, pose_cam)` 이 `_project_local_planar()` 로 간다:
  - 파트 회전 = wrap(포즈 시점 각도 − 포즈 시점 레스트 각도) − 부모의 같은 값
  - 자식 위치 = 렌더 시점 레스트 오프셋(고정) · 루트(힙) 위치 = 렌더 레스트 머리 + 포즈 시점 머리 이동(px, 크기가 같아 그대로 옮김)
  - `s = 1` · 깊이 `d` 는 렌더 시점(그리기 순서는 여전히 게임 시점)
- 창·익스포터·검사 도구는 `baker.project_local()` / `baker.capture_rest()` 한 통로만 쓴다(평면화 여부를 베이커가 정함). `serialize_view()` 에 `planar`·`pose_yaw` 가 들어가 P7 의 이어 담기 검사가 평면화/비평면화 섞임을 거절한다.
- 실측(−55° · 512px · 레스트 Walk 88%): 평면화 Jog_Fwd 는 3D 대비 실루엣 30~53% 어긋나지만(의도된 것) 팔다리가 전부 제 길이로 화면 안에서 흔들린다(L_UpperArm 83° · R_Thigh 117°). 3D 투영은 8~12% 지만 팔이 앞뒤로 접힌다.
- 한계: 옆으로 벌리는 동작(점핑잭)은 측면 포즈 시점에서 단축돼 각도가 불안정 → `동작 시점 Yaw` 를 0 으로. 몸통 비틀림·깊이 회전은 여전히 없다.

  - 기준을 "지난번 sets.json 에 적혀 있던 것"으로 잡은 이유: "`rig.json` + `puppet.tscn` 이 있는 하위 폴더"로 잡으면 같은 출력 폴더 아래에 따로 구운 다른 캐릭터까지 지운다. 그래서 그 전부터 남아 있던 찌꺼기(지난번 sets.json 에도 없는 것)는 못 치운다 — 의도한 것.
  - 툴이 만든 파일만 지운다(`puppet.tscn`·`puppet_pixel.tscn`·`rig.json`·`parts/*.png`·`*.png.import`). 다른 파일이 있으면 그 파일·폴더는 남기고 결과의 `left_dirs` 로 알린다(치운 건 `removed_dirs`, 창의 완료 글에 나온다).
  - ⚠ 폴더 이름은 **대소문자를 가리지 않고** 견준다 — Windows 에서 `stand` 와 `Stand` 는 같은 폴더라, 가려 견주면 이름의 대소문자만 바꿨을 때 방금 구운 폴더를 지운다. 같은 이유로 굽기 전에 디스크의 폴더 이름도 새 글자에 맞춘다(`_match_dir_case` — 안 맞추면 `sets.json` 경로와 글자가 달라 대소문자를 가리는 플랫폼에서 못 연다).
  - `sets.json` 을 손으로 고쳐 `..` · `a/b` 가 들어와도 밖을 지우지 않게 "폴더 이름 하나"(`validate_filename()` 과 같고 `.` 로 시작 안 함)만 받는다.
- 검사: `tools/sets_check_cli.gd`(세트 2개 → 폴더 2개, 씬 애니, rig.json 레스트가 세트별, 몸통 그림 크기가 다름, sets.json 순서, **[5] 옛 폴더 정리**) · 스모크 26(창 편집·프리셋 왕복).

### 4-18. 레스트 자세 — 이 도구에서 가장 큰 레버 (09-15)
- 파트 그림은 **레스트 한 자세**에서만 찍힌다. 어떤 파트가 거기서 카메라를 향해(단축률 낮음) 짧고 얇게 찍히면, 그 파트가 화면과 나란해지는 동작마다 3D 와 크게 어긋난다. −55° 의 `Idle` 은 오른발이 카메라를 향해(0.41) Walk 의 오른 종아리·발이 35~60% 어긋났고, Walk 25% 를 레스트로 쓰면 5% 로 떨어진다(02 P8).
- `DRRigModel.foreshortening(skel, cam, view_h_px)` = 파트별 화면 길이 ÷ 실제 뼈 길이(0~1). 창의 `레스트 자세 자동`(→ 4-21) 과 수동 버튼 `이 애니에서 자세 찾기`(레스트 칸 애니 안에서 시점만) / `고른 동작에서 찾기`(5번 선택, 없으면 전체)는 1초당 12프레임씩 훑어 **파트 최소값이 가장 큰 프레임**을 고른다(힙·머리·손은 tail 이 짧거나 작아 제외). 범위를 둘로 나눈 이유: 레스트를 `Crawl_Bwd` 로 두고 눌렀는데 6번의 `Walk` 로 바뀌면 "이 애니의 몇 %" 를 기대한 사용자에겐 오동작으로 보인다. 애니가 바뀌면 파트 그림도 바뀌므로 다시 굽는다.
- **자세 그룹**: 서기 계열과 엎드리기(Crawl)·수영처럼 몸의 방향이 다른 계열은 한 레스트로 못 덮는다 → 계열마다 **그 계열 프레임을 레스트로, 다른 출력 폴더**에 굽고 게임이 상태별로 씬을 바꾼다. 같은 폴더에 다른 레스트가 섞이는 건 `_incompatible_reason()` 이 막는다(4-5 / 02 P7).
- 레스트 시점 슬라이더(0~1)는 `_current_opts()` 가 `길이 × 슬라이더` 초로 환산해 `opts.rest_time` 에 넣고, 프리뷰·베이크·`serialize_view()` 가 전부 그 값을 쓴다(02 C10 — 예전엔 베이크가 항상 0% 였음).

### 4-17. 부드러운 도트 이동 (09-15)
- 문제: 2D 재생에서 1픽셀 미만 움직임마다 도트 칸이 통째로 켜졌다 꺼졌다 해서 몸통 안쪽이 TV 노이즈처럼 깜빡였다(→ 02 P5). 계단 재생(12fps 로 끊기)은 사용자가 기각 — 부드러운 움직임은 유지해야 한다.
- 두 가지를 **같이** 쓴다. 하나만으로는 효과가 없다(확대만 = 지금과 같음, 셰이더만 = 섞을 화면 픽셀이 없음).
  1. **화면 배율로 그리기** — 2D 퍼펫 SubViewport 를 `캔버스 × 화면 배율`(1~8배)로 키우고 퍼펫 루트를 같은 배율로 스케일한다(`_apply_puppet_scale()`). 프리뷰 TextureRect 는 1:1 로 붙인다. 파트 이미지·베이크는 그대로.
  2. **`runtime/smooth_pixel.gdshader`** — 텍셀 안쪽은 또렷하게, 텍셀 경계만 `fwidth` 기준 화면 1픽셀 폭으로 섞는다. `texelFetch` 로 4텍셀을 읽어 알파를 미리 곱한 뒤 섞는다(텍스처 필터로 섞으면 투명 텍셀의 검정이 섞여 테두리에 어두운 선).
- 확대 계산은 텍스처 크기가 아니라 `_pv_logical`(원래 크기)로 한다. 2D 퍼펫 텍스처는 확대할 때마다 커지므로 텍스처 크기를 쓰면 "해상도가 바뀌었다"고 보고 확대가 풀린다. 채움 % 도 `_puppet_scale` 로 나눠 캔버스 픽셀로 센다.
- 베이크: `art` 스프라이트가 ShaderMaterial 1개를 공유(씬에 한 번만 저장), `rig.json` 에 `"smooth_pixel"`.
- **도트 아웃라인**(09-16) — 두 방식, 창 상단 바 `전체 실루엣` 체크로 고른다(기본 켬):
  - **전체 실루엣**(`outline_whole`, 기본) = **밑깔개**: 파트마다 `stretch/outline` 스프라이트를 하나 더 둔다(본체 `art` 와 같은 텍스처·자리, 절대 z `DRExporter.OUTLINE_Z` = −1 → 모든 파트 뒤). 머티리얼은 같은 셰이더에 `outline_only = true` — 실루엣을 `outline_px` 텍셀만큼 부풀린 모양을 선 색 한 색으로 그린다(부드러운 이동이 켜져 있으면 알파만 같은 방식으로 섞음). 파트 본체가 그 위를 덮으므로 관절 겹침은 가려지고 **캐릭터 전체 바깥 테두리만** 남는다. 장비도 `DRPuppet.equip()` 이 같은 밑깔개(`equip_<슬롯>_outline`, `get_equipped_outline()`)를 붙인다 — 장비 그림에도 선 두께만큼 투명 여백이 있어야 바깥에 선이 생긴다.
  - **파트별**: 파트 셰이더의 uniform `outline_px`·`outline_color` — 투명 텍셀 중 맨해튼 거리 `outline_px` 안에 불투명 텍셀이 있으면 선. 파트마다 자기 z 에서 그려지므로 관절 겹침에도 선이 생긴다. 밑깔개는 만들지 않는다(창에서는 숨김).
  - 두 방식 모두 두께 단위는 텍셀(= 도트)이라 카메라 줌·노드 배율과 무관하고, 텍스처 밖에는 못 그리므로 익스포터가 파트 그림을 `outline_px` 만큼 `grow` 해서 자른다.
  - ✗ **CanvasGroup 방식은 안 됨**(09-16 시도 후 폐기, 02 M2): 루트를 CanvasGroup 으로 모아 그리면 `z_index` 가 그룹과 다른 자식은 그룹에서 빠져 따로 그려진다 → 프레임마다 z 가 바뀌는 퍼펫에는 못 쓴다.
  - 본체 머티리얼은 부드러운 이동·파트별 아웃라인 중 하나라도 켜면 붙는다(창 `_apply_part_material` / 익스포터 같은 규칙). 프리셋 `outline_px`·`outline_color`·`outline_whole`, cfg 동일 키, rig.json `outline_mode` whole/parts. 검사: 스모크 29(전체 실루엣은 **캐릭터 안쪽 픽셀 0개 변화**, 파트별은 관절 선으로 안쪽이 바뀜) · 스모크 18(퍼펫 뷰포트 = CPU 합성) · `sets_check`(두 모드 씬 구조·uniform·파트 그림 여유·장비 밑깔개) · `equip_test_cli`(밑깔개 있는 씬이면 장비 밑깔개도 같은 머티리얼·z).
- `DRPuppet.equip()` 은 본체 `art` 의 머티리얼을 장비 스프라이트에도 붙인다(결이 달라지지 않게). CLI 는 `--nosmooth` 로 끈다. 프리셋 `smooth_pixel`.
- 게임에서는 캐릭터를 **확대해서** 그릴 때만 효과가 있다. 1:1 로 그리면 nearest 와 거의 같다.
- 실측(흐린튐): Idle 25.5 → 4.9(움직임 양 19.4 → 19.3 그대로), Jog_Fwd 343 → 332(3D 렌더 331 과 같은 수준 — 남은 건 동작 자체).
- 검사: 스모크 21번 · 19번(프리셋 왕복) · `equip_test_cli`(장비 머티리얼 = 본체).

## 5. 데이터 포맷

### 출력 폴더
```
<out_dir>/
  parts/<파트>.png     used_rect 로 크롭한 파트 이미지
  rig.json             아래 참조
  puppet.tscn          바로 쓰는 2D 퍼펫
```
에디터 `베이크` 버튼은 저장 → 파일시스템 scan 완료 대기 → `rebuild_scene()` 으로 **임포트된 PNG 를 참조하도록** 씬을 다시 저장한다. CLI 베이크는 임포트 전이라 이미지를 씬에 **임베드**(ImageTexture)한다.

**같은 폴더에 다시 구우면**(`keep_previous`, 기본 켬) 저장 전에 예전 rig.json 의 애니를 읽어 이번 애니와 합친다(같은 이름은 이번 것). 애니 값(위치·회전)이 "레스트 포즈를 이 카메라로 찍은 기준"의 상대값이라 **레스트 포즈·해상도·Ortho·카메라 기저/위치·파트 이름 목록이 같을 때만** 섞고, 다르면 예전 애니를 빼고 `dropped_reason` 에 이유를 남긴다(→ 02 P7). 파트 PNG 는 이름별로 덮어쓰기만 하므로 **예전에만 있던 파트 그림(예: 발가락 분리 때의 `L_Toe.png`)은 폴더에 남는다**.

### rig.json
```jsonc
{
  "version": 1,
  "view": {                        // DRBaker.serialize_view() — 장비를 같은 카메라로 구울 때 복원용
    "yaw", "pitch", "ortho_size", "size": [w, h], "supersample",
    "rest_anim", "rest_time",
    "camera_basis": [9개], "camera_origin": [3개]
  },
  "parts": [{
    "name", "parent", "layer", "root_bone", "bones",
    "image": "parts/Head.png",
    "crop": [x, y, w, h],          // 캔버스 기준
    "rest": { "head": [x, y], "angle", "len", "depth" }
  }],
  "z_order": ["뒤", "...", "앞"],        // 파트 단위 (layer_order 를 펼친 것)
  "layer_order": ["뒤", "...", "앞"],    // 그리기 순서 목록(레이어) — 발가락 줄 없음
  "z_order_manual": true,
  "smooth_pixel": true,                // 파트 스프라이트에 runtime/smooth_pixel.gdshader 를 붙였는지
  "animations": {
    "Jog_Fwd": { "fps", "length", "loop",
      "frames": [{ "t", "parts": { "Head": { "p": [x, y], "r", "s", "d", "z" } } }] }
  },
  "unmapped_bones": []
}
```
`p` = 부모 기준 로컬 위치, `r` = 로컬 회전(라디안, 펴진 값), `s` = 축방향 배율, `d` = 깊이, `z` = 뒤에서부터 순번.

### puppet.tscn
```
Puppet (Node2D, DRPuppet 스크립트)
├ Skeleton2D
│  └ Bone2D "Hips"                       ← 계층은 rig.json parent 대로
│     ├ stretch (Node2D) → art (Sprite2D)  ← 부드러운 도트 이동이면 material = smooth_pixel (전 파트 1개 공유)
│     ├ Bone2D "Torso" → ...
│     └ Bone2D "L_Thigh" → ...
└ AnimationPlayer
     트랙: <bone>:position · <bone>:rotation · <bone>/stretch:scale · <bone>/stretch/art:z_index(자동일 때만)
```
Bone2D 는 `set_autocalculate_length_and_angle(false)` + 길이·각도 직접 지정(말단 본 경고 방지, 에디터 기즈모용).

### DRPreset (`.tres`)
`model_path, note` · 시점 `yaw, pitch, ortho, auto_fit, margin` · 도트화 `resolution, supersample, light_bands, ambient, alpha_threshold, color_levels` · 파트 `bleed_rings, z_auto, z_order(레이어 이름, 뒤→앞)` · 포즈 `rest_anim, rest_time, animations, fps, apply_stretch, smooth_pixel` · 출력 `out_dir`

### DREquipItem / DRPuppet
- `DREquipItem`: `slot, part, texture, offset(레스트 기준 이미지 좌상단 캔버스 좌표), z_index, follow_stretch, modulate`
- `DRPuppet`: `equip(item)`(같은 슬롯이면 교체) · `unequip(slot)` · `unequip_all()` · `get_equipped(slot)` · `tint_part(part, color)` · `part_names()` · 시그널 `equipped / unequipped`
- 런타임에 rig.json 을 안 읽는다. 레스트 피벗 = 조상 Bone2D `rest.origin` 누적합, 레스트 각도 = `get_bone_angle()`.
- 장비 배치 규격은 파트 본체 `art` 와 같다: `rotation = -rest_angle`, `position = (offset − rest_head).rotated(-rest_angle)`.
- 장비 스프라이트의 머티리얼은 본체 `art` 의 머티리얼을 그대로 쓴다(부드러운 도트 이동으로 구웠으면 장비도 같은 셰이더, 아니면 없음).
