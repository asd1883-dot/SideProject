# Dot Rigger — 설계와 구조

> 작성 2026-09-14 · 대상 코드 `addons/dot_rigger/` (마지막 코드 변경 2026-09-09, 09-14 테스트 폴더 생성 1줄)
> 사용법(버튼·조작)은 [`addons/dot_rigger/README.md`](../../addons/dot_rigger/README.md). 이 문서는 **왜 이렇게 만들었는지**를 남긴다.

## 1. 무엇을, 왜

### 출발점
처음 구상은 창 두 개였다.

- **A뷰** — 3D 모델을 불러와 X·Y·Z 각도를 정하고, 도트화 셰이더를 입혀 스프라이트를 뽑는다.
- **B뷰** — 뽑은 이미지를 손·발·관절 레이어로 나눈다(스파인과 비슷).

### 결론: 프레임 스프라이트가 아니라 **컷아웃 퍼펫**
목적이 "옷·무기·장구류를 갈아입는 캐릭터"라서, 프레임을 통째로 굽는 방식은 장비 종류만큼 이미지가 **곱으로** 늘어난다. 파트를 본에 붙이는 컷아웃이면 장비 1종 = 이미지 1장, **합으로** 늘어난다.

| 헬멧 1종 추가 시 필요한 이미지 | 장수 |
|---|---|
| 프레임 베이크 — 최초 가정 (8방향 × 애니 6 × 12프레임) | 576 |
| 프레임 베이크 — 확정 조건 (1방향 × 애니 6 × 12프레임) | 72 |
| **컷아웃 부착 (이 도구)** | **1** |

### 사용자가 확정한 조건

| 항목 | 결정 |
|---|---|
| 시점 | A뷰에서 정한 **각도 하나로 고정**. 게임은 그 각도만 보여준다 |
| 애니메이션 | **3D 애니메이션의 본 각도를 투영해 자동 생성**. 2D에서 손으로 키를 찍지 않는다 |
| 대상 | **휴머노이드 우선**. 탱크·중장비는 나중에(파트 프로필만 추가하면 됨) |
| 그리기 순서 | 자동(3D 깊이) 기본 + 수동 고정 순서. **사용자는 수동을 쓰는 중** |

### B뷰는 따로 만들지 않았다
관절에서 자르는 위치(본 웨이트), 피벗(본 투영), 계층(본 부모 관계)이 **3D에서 전부 자동으로 확정**된다. 사람이 할 일은 **그리기 순서 지정과 검수**만 남아서, 별도 창 대신 A뷰 오른쪽 **"그리기 순서" 열**로 흡수했다.

## 2. 파이프라인

```
.glb  (스킨드 메쉬 1개 + Skeleton3D + AnimationPlayer)
  │
  ├─ part_profile   본 이름 → 파트 이름 (정규식 규칙, 좌우 접두/접미 정규화)
  ├─ mesh_splitter  정점마다 웨이트가 가장 큰 본 → 파트. 파트별 ArrayMesh 로 분해 (+관절 겹침 링)
  ├─ rig_model      파트 계층 · 루트 본(살 붙은 본만) · tail 점 · 3D→2D 투영
  ├─ baker          SubViewport + 직교 카메라 + 도트 셰이더. 파트를 한 장씩 단독 렌더
  ├─ exporter       parts/*.png + rig.json + puppet.tscn (Skeleton2D + AnimationPlayer)
  └─ runtime        DRPuppet.equip(DREquipItem) — 장비를 파트에 부착
```

## 4. 설계 결정과 이유

### 4-1. 파트는 노드 계층이 아니라 **본 웨이트**로 자른다
리깅된 캐릭터는 팔·손이 별도 메쉬가 아니다. UAL1도 메쉬는 `Mannequin` 하나, 본은 65개(그중 손가락이 40개). 노드 하이어라키로는 손·팔뚝을 나눌 수 없다. 정점마다 웨이트가 가장 큰 본(argmax)을 찾아 파트를 정한다 — 추측이 아니라 모델에 이미 들어 있는 데이터다.

### 4-2. 셰이더 마스킹 대신 **메쉬 자체를 파트별로 분해**
- 파트마다 `MeshInstance3D`가 따로 생겨 **에디터에서 눈으로 확인**할 수 있다.
- 관절 겹침(bleed)이 삼각형 배정 규칙만으로 공짜로 생긴다.
- 정점 배열은 원본을 그대로 공유하고 **인덱스 배열만** 파트별로 바꾼다(리맵 비용 없음).

### 4-3. 삼각형 배정과 **관절 겹침 링**
- 규칙: **"정점 하나라도 이 파트면 이 삼각형을 가져간다."** → 경계 삼각형이 양쪽에 다 들어가 구멍이 없다.
- `bleed_rings` 만큼 삼각형 한 겹씩 더 확장한다.
- **관절에서만 자란다.** 바깥 실루엣은 이웃 파트와 안 닿으니 안 자란다.
  실측 `L_Calf`: 가로 18px 고정, 세로 50 → 53 → 57px (링 0/1/2). 발목 겹침 픽셀 링0=15px, 링2=106px.
- **전체 공통 값**이다. 관절별로 따로 못 정한다.
- 목적: 2D에서 관절을 굽힐 때 이음새가 벌어지는 틈을 메운다. 대가: 넓을수록 이웃 살점을 들고 다녀서 순서가 어긋나면 경계에 턱이 보인다. 그리기 순서 문제는 이 값으로 못 고친다(yaw −45° 에서 링 1·링 0 모두 불일치 5.9%).

### 4-4. 파트는 **단독 렌더**한다 (3D 합성의 반대)
컷아웃은 팔을 돌리면 몸통에 가려졌던 부분이 드러나야 하므로, 파트 이미지는 **가려진 부분까지 온전해야** 한다. 나머지 파트를 숨기고 한 장씩 찍는다.

### 4-5. 루트 본 = 파트 안 최상위 본 **중 정점 웨이트가 있는 본**
UE·Mixamo 리그 맨 위의 `root` 는 웨이트도 없고 제자리 애니메이션에서 안 움직이는 **바닥 기준점**이다. 이걸 피벗으로 잡으면 힙 피벗이 발바닥에 찍히고 힙·상체가 고정된다(→ 버그 C3). 그래서 splitter 가 모은 `weighted_bones` 만 후보로 본다. 이름으로 거르지 않는 이유: 리그마다 기준점 본 이름이 다르다.

### 4-6. tail 점 — 리그 규격에 의존하지 않는 각도 계산
파트마다 "루트 본 공간에 고정된 점(`tail_local`)"을 하나 잡는다. 어떤 프레임이든 **head·tail 두 점만 카메라로 투영**하면 2D 각도 · 화면상 길이(단축률) · 깊이가 나온다. 본의 로컬 축 방향(리그마다 다름)을 몰라도 된다.

tail 위치 결정 순서:
1. 파트 말단 본들의 자식 중 **파트 밖으로 나가는 본**들의 레스트 위치 평균
2. 없으면 말단 본 자체 위치 평균 (말단이 루트 하나뿐이면 제외)
3. 그래도 없으면 부모→루트 방향으로 0.1 연장

### 4-7. 애니메이션은 **레스트 대비 델타 + 위치 트랙까지**
- Bone2D 레스트 회전은 0, 위치는 부모 기준. 애니 회전 = (현재 월드각 − 레스트 월드각) − 부모의 같은 값.
- **위치 트랙도 넣는다.** 3D 투영은 2D 강체 계층으로 딱 떨어지지 않아(단축 때문에) 회전만 넣으면 관절이 흘러간다. 위치를 투영값에 맞추면 정확히 일치한다.
- 각도는 `atan2` 경계에서 360° 튀므로 프레임 순서대로 펴고(unwrap), 루프 애니는 0프레임 사본을 끝에 붙여 이음새를 닫는다.
- 샘플은 `[0, length)`(루프) / `[0, length]`(비루프), 기본 12fps.
- 이 계산은 `DRRigModel.project_local()` 하나로 모았다 — **베이크와 2D 프리뷰가 같은 코드**를 쓴다.

### 4-8. 단축 보정 (stretch)
팔이 카메라 쪽으로 돌면 화면상 길이가 짧아지는데 강체 스프라이트는 이걸 못 해서 관절이 떨어져 보인다. 측면 시점 실측: 다리·몸통·머리 0.99~1.02, **팔 0.69~1.05**.
노드 구조:
```
Bone2D(파트)            position / rotation 애니
 └ stretch (Node2D)     rotation = rest_angle,  scale = (s, 1) 애니   ← 본 축을 x 에 맞춰 x 만 늘림
    └ art (Sprite2D)    rotation = -rest_angle, position = R(-rest_angle)·(crop원점 − rest_head)
```
`s` 는 1/1.6 ~ 1.6 으로 제한. 끌 수 있다(끄면 도트 결은 깨끗하지만 팔 관절이 벌어질 수 있음).

### 4-9. 그리기 순서 (z)
- 깊이 = **head~tail 평균**의 카메라 공간 z. 긴 파트(전완·허벅지)는 루트 본 한 점의 깊이가 파트 전체를 대표하지 못한다.
- 내림차순 정렬 = 먼 것부터 = 먼저 그림.
- **자동**: 프레임마다 z 트랙(`UPDATE_DISCRETE` + `INTERPOLATION_NEAREST`). **수동**(`z_override`): 순서를 모든 프레임에 고정하고 z 트랙을 만들지 않는다.
- 애니를 안 틀어도 맞도록 **정지 상태 z_index 도 씬에 박는다**.
- Sprite2D 는 `z_as_relative = false` (Bone2D 가 중첩돼 있어 상대값이면 누적됨).

### 4-10. 자세 고정은 `speed_scale = 0` — `pause()` 금지
`set_pose()` = `play()` → `seek(t, true)` → `advance(0)`. AnimationPlayer 는 setup 에서 `speed_scale = 0` 으로 세워 둔다.
- 재생 중이면 파트 15장을 찍는 사이 자세가 흐른다(→ C1).
- `pause()` 는 믹서가 자세 적용을 멈춰 **바인드 포즈로 돌아간다**(→ C2).
- 프리뷰 재생은 `set_playback(true)` 로 speed_scale 만 1로. 베이크는 항상 `set_pose()` 를 거치므로 영향 없음.

### 4-11. 프리뷰 두 모드
| 모드 | 방식 | 순서 반영 | 재생 |
|---|---|---|---|
| 3D (기본) | 파트 메쉬를 3D 로 렌더, z버퍼가 픽셀마다 판정 = **정답** | ✗ | 엔진이 직접(speed_scale 1) |
| **2D 순서** | 파트 이미지 캐시 + **베이크 씬과 같은 노드 구조 퍼펫**을 `project_local()` 로 움직임 = **베이크 결과 미리보기** | ✓ | `_process` 에서 투영 |

- 2D 캐시는 캔버스 전체 크기 이미지(크롭 안 함)라 레스트에선 (0,0) 에 놓으면 맞는다.
- 캐시 키 `_render_sig()` = 시점 값 + 겹침 링 + 명암 단계 + 앰비언트 + 알파 + 색 양자화.
- `_process` 는 `_busy` 동안 자세를 절대 안 건드린다(→ P3).

### 4-12. 창과 캐시
- 창 X = `hide()` 만. 불러온 모델·설정 유지가 목적. 코드 수정 후엔 `창 새로 만들기(초기화)` 메뉴.
- `_fit_sig` — 시점 값이 바뀔 때만 카메라 재설정·자동 맞춤(렌더 3번짜리라 클릭마다 하면 느림).
- `_dirty` — 갱신 중 들어온 요청을 버리지 않고 끝나고 한 번 더.
- `_fill_z_list()` — 순서가 그대로면 목록을 안 건드림(clear 하면 다중 선택이 날아감). 바뀌면 **이름으로** 선택 복원.
- `_iso_parts` — 드롭다운·파트 트리·그리기 순서 목록이 공유하는 "프리뷰 대상 파트 집합"(빈 집합 = 전체).
- 창 전체 `auto_translate_mode = DISABLED` — 에디터가 "Idle" 을 "대기" 로 번역해 보여줬음.
- 파일 대화상자는 **툴 창의 자식**으로 붙인다(에디터 본체에 붙이면 툴 창이 뒤로 밀림). `EditorFileDialog` 가 null 이면(에디터 밖) `FileDialog` 로.

### 4-13. 프리셋은 `.tres` 리소스
파일시스템 독에 보이고, **툴을 안 열어도 인스펙터에서 값 확인·수정**이 된다(비개발자 팀원 대상). 복원은 인덱스가 아니라 **이름**으로(모델이 바뀌면 인덱스 무의미). 적용 중엔 `_loading` 으로 프리뷰 갱신을 막고 끝에 한 번.

### 4-14. 도트화
- 셰이더 `dot_flat` 은 unshaded 로 조명을 직접 계산해 N단(기본 3) 계단화. 원본 `BaseMaterial3D` 의 albedo 색/텍스처를 가져온다.
- 뷰포트: 직교 카메라, MSAA/SSAA/TAA/디밴딩 끔, 톤매핑 Linear, 투명 배경, `own_world_3d`.
- 후처리는 CPU(`_post`): 알파 임계(0/1 로 딱 자름) + 색 양자화. 슈퍼샘플 >1 이면 크게 찍고 bilinear 축소.
- 카메라 자동 맞춤: 합성 렌더의 `used_rect` 를 보고 중심→배율 순으로 최대 3번 수렴. 여백은 **픽셀 고정**.

## 5. 데이터 포맷

### 출력 폴더
```
<out_dir>/
  parts/<파트>.png     used_rect 로 크롭한 파트 이미지
  rig.json             아래 참조
  puppet.tscn          바로 쓰는 2D 퍼펫
```
에디터 `베이크` 버튼은 저장 → 파일시스템 scan 완료 대기 → `rebuild_scene()` 으로 **임포트된 PNG 를 참조하도록** 씬을 다시 저장한다. CLI 베이크는 임포트 전이라 이미지를 씬에 **임베드**(ImageTexture)한다.

### rig.json
```jsonc
{
  "version": 1,
  "view": {                        // DRBaker.serialize_view() — 장비를 같은 카메라로 구울 때 복원용
    "yaw", "pitch", "ortho_size", "size": [w, h], "supersample",
    "rest_anim", "rest_time",
    "camera_basis": [9개], "camera_origin": [3개]
  },
  "parts": [{
    "name", "parent", "root_bone", "bones",
    "image": "parts/Head.png",
    "crop": [x, y, w, h],          // 캔버스 기준
    "rest": { "head": [x, y], "angle", "len", "depth" }
  }],
  "z_order": ["뒤", "...", "앞"],
  "z_order_manual": true,
  "animations": {
    "Jog_Fwd": { "fps", "length", "loop",
      "frames": [{ "t", "parts": { "Head": { "p": [x, y], "r", "s", "d", "z" } } }] }
  },
  "unmapped_bones": []
}
```
`p` = 부모 기준 로컬 위치, `r` = 로컬 회전(라디안, 펴진 값), `s` = 축방향 배율, `d` = 깊이, `z` = 뒤에서부터 순번.

### puppet.tscn
```
Puppet (Node2D, DRPuppet 스크립트)
├ Skeleton2D
│  └ Bone2D "Hips"                       ← 계층은 rig.json parent 대로
│     ├ stretch (Node2D) → art (Sprite2D)
│     ├ Bone2D "Torso" → ...
│     └ Bone2D "L_Thigh" → ...
└ AnimationPlayer
     트랙: <bone>:position · <bone>:rotation · <bone>/stretch:scale · <bone>/stretch/art:z_index(자동일 때만)
```
Bone2D 는 `set_autocalculate_length_and_angle(false)` + 길이·각도 직접 지정(말단 본 경고 방지, 에디터 기즈모용).

### DRPreset (`.tres`)
`model_path, note` · 시점 `yaw, pitch, ortho, auto_fit, margin` · 도트화 `resolution, supersample, light_bands, ambient, alpha_threshold, color_levels` · 파트 `bleed_rings, z_auto, z_order(뒤→앞)` · 포즈 `rest_anim, rest_time, animations, fps, apply_stretch` · 출력 `out_dir`

### DREquipItem / DRPuppet
- `DREquipItem`: `slot, part, texture, offset(레스트 기준 이미지 좌상단 캔버스 좌표), z_index, follow_stretch, modulate`
- `DRPuppet`: `equip(item)`(같은 슬롯이면 교체) · `unequip(slot)` · `unequip_all()` · `get_equipped(slot)` · `tint_part(part, color)` · `part_names()` · 시그널 `equipped / unequipped`
- 런타임에 rig.json 을 안 읽는다. 레스트 피벗 = 조상 Bone2D `rest.origin` 누적합, 레스트 각도 = `get_bone_angle()`.
- 장비 배치 규격은 파트 본체 `art` 와 같다: `rotation = -rest_angle`, `position = (offset − rest_head).rotated(-rest_angle)`.

## 6. 기본 휴머노이드 프로필 — UAL1 실측

규칙(순서대로 첫 매치): 좌우 표기(`left*`/`right*`/`l_`/`r_`/`*_l`/`*_r`/`.l`/`.r`, `mixamorig:` 접두 제거)를 떼고 핵심 이름을 정규식으로 본다. `root|pelvis|hip`→Hips, `spine|chest|torso`·`clavicle|shoulder`→Torso, `neck|head|jaw|eye`→Head, `upperarm`→UpperArm, `lowerarm|forearm`→Forearm, `hand|index|middle|pinky|ring|thumb|finger`→Hand, `thigh|upleg`→Thigh, `calf|shin|lowerleg|^leg`→Calf, `foot|ball|toe|ankle`→Foot, 마지막 `arm`→UpperArm(Mixamo `LeftArm`).

| 파트 | 본 | 삼각형 |
|---|---|---:|
| Hips | root, pelvis (**루트 본 = pelvis**) | 462 |
| Torso | spine_01~03, clavicle_l/r | 1064 |
| Head | neck_01, Head | 542 |
| L/R_UpperArm | upperarm | 325 |
| L/R_Forearm | lowerarm | 220 |
| L/R_Hand | hand + 손가락 20본 | 4913 |
| L/R_Thigh | thigh | 256 |
| L/R_Calf | calf | 289 |
| L/R_Foot | foot, ball, ball_leaf | 218 |

65본 → 15파트, 미매핑 0. 손가락은 캐릭터 키 96px 이하에서 2~3픽셀이라 파트로 나눌 의미가 없어 Hand 하나로 접는다.

```
Hips
├─ L_Thigh → L_Calf → L_Foot
├─ R_Thigh → R_Calf → R_Foot
└─ Torso
   ├─ Head
   ├─ L_UpperArm → L_Forearm → L_Hand
   └─ R_UpperArm → R_Forearm → R_Hand
```

UAL1 애니메이션은 120개. **glTF 임포터가 `_Loop` 접미사를 떼고 loop_mode 로 바꾼다**(`Idle_Loop` → `Idle`, `Jog_Fwd_Loop` → `Jog_Fwd`). `DRBaker.resolve_anim()` 이 원래 이름으로 불러도 찾아준다.
