## 검증

렌더가 필요한 도구는 **창이 잠깐 떴다 닫힌다.** `--headless` 로는 SubViewport 가 안 그려져서 쓸 수 없다(`bake_cli --diag` 만 예외). 출력을 받으려면 `_console.exe` 를 쓴다.

**Git Bash**
```bash
G="/c/<경로>/Godot_v4.7.2-stable_mono_win64/Godot_v4.7.2-stable_mono_win64_console.exe"
P="C:/<경로>/SideProject"

"$G" --headless --path "$P" --import                                                     # ① 스크립트 등록 (새 class_name 추가 후에도 필수)
"$G" --headless --path "$P" --script res://addons/dot_rigger/tools/bake_cli.gd -- --diag   # ② 본→파트 매핑
"$G" --path "$P" --resolution 1280x860 --script res://addons/dot_rigger/tools/ui_smoke_cli.gd       # ③ 에디터 창 전체
"$G" --path "$P" --resolution 400x300  --script res://addons/dot_rigger/tools/rootbone_check_cli.gd # ④ 파트 피벗
"$G" --path "$P" --resolution 400x300  --script res://addons/dot_rigger/tools/drift_check_cli.gd    # ⑤ 자세 고정
"$G" --path "$P" --resolution 400x300  --script res://addons/dot_rigger/tools/layer_check_cli.gd    # ⑥ 발(발가락 합침)/레이어
"$G" --path "$P" --resolution 400x300  --script res://addons/dot_rigger/tools/anim_merge_check_cli.gd # ⑦ 같은 폴더에 여러 번 구우면 애니가 쌓이는지
```

**PowerShell**
```powershell
$G = "C:\<경로>\Godot_v4.7.2-stable_mono_win64\Godot_v4.7.2-stable_mono_win64_console.exe"
$P = "C:\<경로>\SideProject"
& $G --path $P --resolution 1280x860 --script res://addons/dot_rigger/tools/ui_smoke_cli.gd
```

## 남은 일

1. **장비 3D 베이크 모드** — 지금은 런타임 부착만 된다(검증에 쓴 헬멧 PNG 는 손으로 만든 것). 캐릭터와 같은 카메라(`rig.json` 의 `view` → `DRBaker.apply_view()`)·같은 레스트 포즈로 장비 메쉬를 구워 `DREquipItem`(오프셋 자동 계산 포함)을 만드는 흐름이 필요하다.
2. **자세 그룹을 창에서 관리** — 지금은 "계열마다 6번 선택·자세 찾기·출력 폴더를 바꿔 다시 굽는" 수동 워크플로다([02 P8](02_버그와_교훈.md)). 그룹(이름·레스트·애니 목록·폴더)을 프리셋에 여러 벌 두고 한 번에 굽는 기능이 있으면 편하다. 게임 쪽에서 상태별 씬 교체도 필요.
3. **부드러운 도트 이동 — 게임 쪽 확인** — 찌글거림은 셰이더로 대응 완료(계단 재생은 사용자가 기각, [02 P5](02_버그와_교훈.md)). 단 효과는 **게임이 캐릭터를 확대해서 그릴 때만** 난다. 게임을 저해상도 화면에 1:1 로 그리고 화면 전체를 키우는 방식으로 만들면 효과가 없으니, 게임 렌더 방식이 정해지면 다시 볼 것. 뛰기처럼 빠른 동작에서 남는 변화는 3D 렌더와 같은 수준(동작 자체)이다.
3. **각도 확정** — 09-15 도트 셰이더 수정(3D 가 깊이를 제대로 쓰게 됨, 02 C9) 뒤 다시 잰 3D 대비 불일치: 정측면 9.4% · **−45° 3.9%** · 사용자 −55° 7.8% · −65° 11.4% (192px, Idle 정지, 자동 순서). 09-14 의 "각도별 4.3~5.9% 로 차이 작음"은 3D 기준 자체가 틀린 값이었고, 그 전의 12~22% 는 자세 드리프트까지 섞인 값이었다([02 §7](02_버그와_교훈.md#7-측정값-모음-근거)). 이 수치는 **레스트 정지 자세의 그리기 순서**만 본 것이라, 동작(공중제비·수영 등)이 화면 안에서 일어나는지와 팔 단축률(`[단축률 진단]`)도 같이 보고 정할 것.
4. **도트화 품질** — 아웃라인 패스, 팔레트 LUT (지금 색 양자화는 단순 계단).
