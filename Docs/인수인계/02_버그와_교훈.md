## 1. 치명 — 구운 결과가 틀리게 나오던 것

### C1. 파트를 찍는 동안 자세가 흘러감
- **발견**: 사용자 "2D 순서 체크하면 왜 재생이 멈추냐" → 역추적해 보니 3D 프리뷰가 **의도치 않게 계속 재생 중**이었음
- **원인**: `set_pose()` 가 `play()` 만 하고 세우지 않음. 파트 15장을 한 장씩(프레임 2개씩 대기) 찍는 사이 자세가 계속 진행
- **실측**: 30프레임 사이 재생 위치 0.033 → 0.605, 같은 파트를 시간차로 두 번 렌더하면 91픽셀 다름
- **해결**: setup 에서 `speed_scale = 0`. 프리뷰 재생만 `set_playback(true)`
- **검사**: `tools/drift_check_cli.gd`

### C2. `pause()` 가 바인드 포즈로 되돌림 (C1 첫 수정의 부작용)
- **발견**: drift 검사에 "서로 다른 자세가 실제로 다르게 찍히는가"를 추가해서
- **원인**: `pause()` 하면 믹서가 자세 적용을 멈춰 스켈레톤이 레스트로 돌아감
- **해결**: `pause()` 금지, speed_scale 0 방식
- **덤으로 틀렸던 것**: 검사 기준으로 `stop()` 을 "바인드 포즈"라 가정했는데 `stop()` 은 **마지막 자세를 그대로 둔다**. 비교 대상을 Idle@0 / Idle@50% / A_TPose 로 바꿈 (814px / 3468px 차이로 정상 확인)

### C3. 힙 루트 본이 `root` — 힙·상체가 고정
- **발견**: 사용자 "스프린트 재생하면 힙하고 상체가 막 고정돼서 안 맞는다". 초기 베이크 때부터 Hips 피벗 y=185(192 캔버스의 발바닥)가 이상했으나 넘어갔었음
- **원인**: 파트 안 최상위 본을 루트로 잡음 → UE 리그 `root` = **정점 웨이트 없음, Jog 중 이동·회전 0.0000**. Torso 는 Hips 의 자식이라 같이 어긋남
- **해결**: 루트 본 후보를 `weighted_bones`(정점을 하나라도 지배하는 본)로 제한 → `pelvis` (Jog 중 이동 0.1214)
- **검사**: `tools/rootbone_check_cli.gd`
- **교훈**: 수치가 이상하면(피벗이 발바닥) 그때 파고들 것

### C4. 회전 ±360° 튐 → 엔진이 키 사이를 한 바퀴 헛돔
- **발견**: 투영값 분석 (`L_Hand −360.4 ~ 5.9`, `R_Foot −367.8 ~ 13.2`)
- **원인**: `atan2` 는 [−π, π] 로 감김. 파이썬 재구성은 프레임을 독립 계산해서 멀쩡해 보였고, **보간하는 엔진에서만** 드러남
- **해결**: `_unwrap_rotations()` + 루프 애니 끝에 0프레임 사본(`_closing_frame`)

### C5. 베이크된 씬의 정지 상태에 z_index 가 없음
- **발견**: 사용자 "yaw −45 로 봤는데 오른쪽 어깨가 몸통에 가려져야 하는데 레이어가 이상"
- **원인**: z 를 애니 트랙에만 넣고 씬엔 안 넣음 → 전부 0 → 씬 트리 순서(팔이 몸통보다 나중)대로 그려짐
- **해결**: `resolve_z_order()` 로 레스트 깊이 순번을 Sprite2D 에 박음. 수동 순서면 그걸로
- **검사 방법**: 3D 합성과 `preview_cli --static` 을 나란히 놓고 차이 맵

### C6. 해상도를 바꿔도 SubViewport 크기가 그대로
- **발견**: 사용자 "도트화에서 해상도 줄였더니 프리뷰 위치가 찐빠"
- **원인**: 뷰포트 크기는 setup 때 한 번만 설정. 자동 맞춤은 UI 의 새 해상도로 중심·배율을 계산 → 어긋남. **베이크에도 같은 문제**
- **해결**: `apply_view_size()` 를 프리뷰 갱신과 베이크 시작 때 호출
- **검사**: 스모크 15번 (192/96/64/256px 에서 중심 오차 ≤0.5px)

### C7. 팔 단축 미보정
- **발견**: 러닝 사이클 재구성에서 팔이 관절에서 떨어져 보임 + 단축률 진단(팔 0.69~1.05)
- **해결**: stretch 노드(근사). 베이크마다 `[단축률 진단]` 출력

### C8. (2026-09-15) Pitch 부호가 반대 — "탑다운"·"아이소" 프리셋이 아래에서 올려다봄
- **발견**: 회전 기즈모의 드래그 방향을 정하려고 잰 값. `pitch = +60` 에서 카메라가 모델 중심보다 **6.4 아래**
- **원인**: `Basis.from_euler` 의 X 회전은 양수일 때 +Z 쪽 점을 아래로 내린다. 그대로 쓰면 +pitch = 아래에서 올려다봄
- **해결**: `DRBaker.view_basis()` 에서 pitch 부호를 뒤집음 → 양수 = 위에서 내려다봄. 사용자 프리셋(pitch 0)은 영향 없음
- **검사**: 스모크 20번 (pitch +60 → 카메라가 모델보다 위)
- **교훈**: "탑다운" 같은 이름표를 달았으면 그 이름대로 보이는지 한 번은 수치로 확인할 것 — 서 있는 인물은 위아래가 반대여도 눈에 잘 안 띈다

### C9. (2026-09-15) 3D 렌더에서 겹친 부분이 비쳐 보임 — 파트 그림까지 틀림
- **발견**: 사용자 "3D 일 때 항상 겹쳐진 부분이 통과돼서 보인다"
- **원인**: `shaders/dot_flat.gdshader` 가 `ALPHA = base.a;` 를 썼다. Godot 4 는 셰이더가 ALPHA 를 쓰기만 해도(값이 1 이어도) 반투명 파이프라인으로 보내고, 반투명 물체는 깊이를 기록하지 않는다 → 픽셀마다 앞뒤를 가리지 못하고 **나중에 그린 면이 위에 올라간다**. 뒤쪽 어깨가 가슴 위로, 엉덩이 관절 안쪽 보라색 면이 허벅지 위로 비쳤다.
- **측정** (`puppet_test/depth_probe.gd`, yaw −55° · 184px, 같은 자세에서 셰이더만 바꿔 비교): 전체 합성 Idle **6.0%** · Jog_Fwd **7.8%** 픽셀이 달랐고, **파트 단독 그림도** 오른손 93px 중 18px · 몸통 1053px 중 38px 가 틀렸다.
- **해결**: `ALPHA_SCISSOR_THRESHOLD = 0.5;` 추가 → 불투명 파이프라인(깊이 기록) + 투명 텍스처는 0.5 기준 오려내기. 알파를 아예 뺀 셰이더와 합성·파트 단독 모두 **0px 차이**.
- **영향**: 수정 전의 3D 프리뷰 · 구운 파트 PNG · `compare_cli` 수치 전부. 3D 대비 불일치 재측정: 정측면 9.4% · −45° 3.9% · −55° 7.8% · −65° 11.4% (09-14 의 4.3~5.9% 를 대체, M1 참고). 결과물은 다시 구울 것(§0).
- **교훈**: 기준("3D = 정답")으로 쓰던 것 자체가 틀려 있었다 — 비교의 기준부터 검증할 것. Godot 셰이더에서 ALPHA 를 쓰면 반투명 취급이므로, 불투명으로 그리려면 알파 가위를 같이 준다.

### M1. (2026-09-14) 드리프트가 비교 측정까지 오염 → 틀린 결론을 사용자에게 전달
- **발견**: 인수인계 검증에서 사용자 각도 −55° 불일치가 4.3% 로 나와 이전 수치(12~22%)와 안 맞음
- **원인**: 각도별 불일치를 C1 수정 **전**에 쟀다. 비교도 파트를 한 장씩 찍으므로 자세가 흘러 차이가 부풀려짐. 같은 도구·같은 각도로 −65° 가 22.2% → 5.5%
- **틀렸던 결론**: "정측면이 3⁄4 보다 확실히 유리" · "−65° 는 불리" · "뭉친 곳은 손·전완" → 실제로는 각도별 4.3~5.9% 로 차이가 작고, 뭉치는 곳은 사타구니
- **09-15 추가**: 이 4.3~5.9% 도 3D 기준이 틀린(C9 — 셰이더가 깊이를 안 씀) 상태에서 잰 값이었다. 셰이더 수정 후 같은 도구로 재측정: 정측면 9.4% · −45° 3.9% · −55° 7.8% · −65° 11.4% — 각도 차이가 다시 커졌다. **비교의 기준(3D)이 맞는지부터 확인할 것.**
- **교훈**: 렌더 경로 버그를 고치면 **그 전에 잰 수치와 거기서 나온 결론을 전부 다시 잴 것**

### M2. (2026-09-16) 전체 실루엣 아웃라인을 CanvasGroup 으로 만들려다 폐기 — 선이 파트 하나에만 생김
- **요청**: 사용자 "파츠별 아웃라인과 진짜 전체 아웃라인을 나누고 전체가 기본"
- **처음 설계**: 퍼펫 루트를 `CanvasGroup` 으로 바꿔 파트를 한 장으로 모은 뒤 셰이더로 테두리 → 코드·문서까지 써 놓고, 작은 실험(빨강 z 1 · 파랑 z 0 사각형)으로 확인하니 선이 **파랑 주위에만** 생기고 빨강은 그룹 밖에서 따로 그려졌다.
- **원인 2가지**: ① CanvasGroup 은 **`z_index` 가 그룹과 다른 자식을 그룹에 넣지 않는다** — 퍼펫 파트는 절대 z 0~14 를 프레임마다 바꾸므로 구조적으로 불가. ② CanvasGroup 셰이더의 그룹 내용은 `TEXTURE` 가 아니라 `hint_screen_texture` + `SCREEN_UV`(TEXTURE 는 흰 기본 텍스처라 그룹 영역이 통째로 칠해짐). 덤: `fit_margin` 은 화면 px 단위(배율·줌과 무관).
- **대응**: **밑깔개** — 파트마다 같은 그림을 선 색으로 부풀려 z −1 에 한 장씩 깔기(01 §4-17). 스모크 29 가 "전체 실루엣은 캐릭터 안쪽 픽셀을 하나도 안 바꾼다(0개)"를 잰다.
- **부작용 막기**: 중간에 `DRPuppet` 을 `extends CanvasGroup` 으로 바꿨더니 루트가 Node2D 인 **예전 씬 전부**가 "Script inherits from native type 'CanvasGroup'" 로 스크립트가 떨어졌다(`--import` 로그에서 발견, 사용자 저장소의 `puppet_test/puppet.tscn` 도 해당). 되돌렸고 `sets_check` 가 Node2D 루트에 스크립트가 붙는지 확인한다.
- **교훈**: 엔진 기능에 기대는 설계는 **코드 쓰기 전에 최소 실험**부터(특히 z_index·그룹·백버퍼처럼 그리기 순서가 얽힌 것). 런타임 스크립트의 상속 클래스를 바꾸면 이미 구운 씬이 깨진다.

### M4. (2026-09-21) "픽셀 퍼펙트"를 다른 기법으로 알아듣고 기능 하나를 통째로 만듦
- **요청**: 사용자 "픽셀퍼펙트 기능 넣기" (한 줄).
- **내가 알아들은 것**: 도트를 격자에 맞춰 그리기(Godot 에서 흔히 말하는 pixel perfect) → SubViewport 래퍼 `puppet_pixel.tscn` · 범위 계산 · 검사 도구까지 만들었다.
- **사용자가 뜻한 것**: "다른 아웃라인을 안 넣어도 색감에 맞게, 가장자리 도트가 그 결의 톤에 맞는 보정식으로 들어가는 것" = **옆 몸 도트 색을 어둡게 한 1도트 선**(3D → 도트 셰이더의 pixel perfect outline / 도트 그림의 selout). 그래서 "카툰 아웃라인과 같이 적용될 수 없으니 토글이어야".

### P8. (2026-09-15) −55° 에서 Walk 는 몸통·발목이 꺾여 보이고 Crawl 계열은 통째로 깨짐 → **레스트 자세가 원인**

### C11. (2026-09-16) 세트 2개 이상을 에디터에서 구우면 앞 세트 퍼펫의 리그가 통째로 깨짐

### C13. (2026-09-21) 앞서 본 애니의 자세가 "트랙 없는 뼈"에 남음 — 합성의 각도 보정이 그냥 Idle 에까지 묻어남

- **원인**: 값을 공용으로 쓴 게 아니다(`upper_keep`·`upper_pitch` 는 합성 정의마다 따로 저장). **뼈대 하나를 모든 애니가 돌려 쓰는데**, 임포터가 레스트와 값이 같은 트랙을 지우므로(`remove_immutable_tracks`) 애니마다 트랙이 있는 뼈가 다르고, AnimationPlayer(`deterministic = false`)는 **트랙이 없는 뼈를 건드리지 않는다.** UAL1 은 120개 애니 전부에 허리 첫 마디 `spine_01` 의 회전 트랙이 없다(늘 레스트). 합성의 방향 유지·각도 보정은 바로 그 뼈(상체의 뿌리)에 트랙을 만들어 쓰므로, 합성을 한 번 세운 뒤의 Idle 은 그 뼈가 돌아간 채였다 — 가슴 방향이 처음 Idle 과 **57°** 차이.
- **그전부터 있던 같은 종류**: Mixamo 동작 7개는 전부 이 뼈(`Spine`)를 6~16° 돌린다 → 09-18 이후 **Mixamo 동작을 본(구운) 직후의 UAL 동작**은 허리가 그만큼 돌아간 채였다. 레스트를 그 상태에서 찍었다면 파트 그림도.
- **해결**: `DRBaker.set_pose()` 가 애니를 세우기 전에 `skeleton.reset_bone_poses()` — "트랙 없음 = 레스트" 라는 원래 뜻대로. 프리뷰·팝업·베이크(`_project_anim`)가 전부 이 함수를 거친다.
- **검사**: `composite_check` [4-2](합성 +30° 를 본 뒤의 Idle 이 새 베이커의 Idle 과 0.000° 차이). 전체 검사 통과.
- **영향**: 09-18 이후 **Mixamo 동작과 UAL 동작을 같이 굽거나, Mixamo 동작을 보다가 구운 결과**는 허리가 최대 16° 틀어졌을 수 있다 → 다시 구울 것. UAL 동작끼리만 구운 결과(`puppet/` 의 Idle·Walk·Sprint)는 영향 없음 — UAL 은 어느 애니도 그 뼈를 안 움직인다.
- **교훈**: 상태를 가진 객체(뼈대) 하나를 여러 애니가 돌려 쓰면 **쓰기 전에 초기화**할 것. "어떤 값이 다른 데까지 묻어난다" → 변수 공유보다 **남은 상태**부터 의심.

### C12. (2026-09-18) 레스트 `(바인드 포즈)` 가 바인드 포즈가 아니라 "마지막에 보던 프레임" 이었음

  | Prone_Firing_Rifle 75% (엎드려쏴) | **15.9%** | — | **21.5%** | 2.7% |

### C10. (2026-09-15) 레스트 시점 슬라이더가 베이크에는 안 감 — 프리뷰는 슬라이더 시점, 베이크는 항상 0%

## 5. Godot · GDScript 함정 요약 — 다음에 또 밟을 것들

**실행 / 렌더링**
- `--headless` 는 더미 렌더러라 **SubViewport 가 안 그려진다**. 렌더가 필요한 CLI 는 창을 띄워서(`--resolution 400x300`) 돌린다. `bake_cli --diag` 만 headless 가능
- 출력을 받으려면 `Godot_..._console.exe`
- `viewport.get_texture().get_image()` 전에 `await RenderingServer.frame_post_draw` 두 번. 대기 없이 다시 읽으면 검은 이미지
- **숨긴 Window 안의 SubViewport 는 렌더되지 않는다**(검은 프리뷰). 베이크 중 창 닫기 금지
- 새 `class_name` 스크립트를 추가하면 `--headless --import` 로 전역 클래스 등록부터

**애니메이션**
- `pause()` → 바인드 포즈로 돌아감 / `stop()` → 마지막 자세 유지 / 고정은 `speed_scale = 0`
- 재생 중인 AnimationPlayer 가 있으면 `await` 사이에 자세가 바뀐다. 여러 장을 한 자세로 찍을 땐 반드시 고정
- glTF 임포트는 `_Loop` 접미사를 떼고 loop_mode 로 바꿈
- z_index 값 트랙은 `UPDATE_DISCRETE` + `INTERPOLATION_NEAREST`
- 각도 트랙은 프레임 순서대로 펴서(unwrap) 넣을 것 — ±180° 를 지나는 비틀림 각도 마찬가지(U35)
- AnimationPlayer(4.7, `deterministic` 꺼짐)는 **트랙이 없는 뼈를 앞 동작 자세로 남긴다** — 동작을 바꿔 쓸 거면 모든 동작이 같은 트랙을 갖게(U35)
- `Animation.compress()` 는 손실 압축 — 회전이 큰 동작에서 수백 mm 튄다. 쓰려면 검사 필수(U35)
- `SceneTree` 스크립트의 `_initialize()` 에서 root 에 붙인 노드는 아직 트리 밖 — `get_viewport_rect()` 같은 것은 `call_deferred` 로 미룬 뒤에(view3d_smoke)
- 창 위치 `--position` 에 음수를 주면 주 모니터로 끌려온다 — 보조 모니터는 `--screen 0`(U35)

**에디터 플러그인 / UI**
- `@tool` 핫리로드는 멤버 변수 추가 같은 구조 변경을 못 따라감
- 에디터는 툴 UI 텍스트를 자동 번역함 → 데이터 표시 창은 `auto_translate_mode` 끄기
- `EditorFileDialog` 는 에디터 밖에서 null. 다이얼로그는 **띄운 창의 자식**으로
- 줄바꿈 없는 Label 은 텍스트 폭이 최소 너비 → 컨테이너 전체를 밀어냄. `clip_text` 는 최소 높이까지 0 으로 만듦
- `ItemList` 다중 선택: `select_mode = SELECT_MULTI`, 신호는 `multi_selected`, 추가 선택은 `select(i, false)`
- 중첩된 CanvasItem 에서 z 를 절대값으로 쓰려면 `z_as_relative = false`
- `CanvasGroup` 은 z_index 가 다른 자식을 그룹에서 뺀다. 그룹 셰이더는 `hint_screen_texture` + `SCREEN_UV` 로 읽는다(M2)
- **가져온(임포트된) 리소스를 메모리에서 고치면 에디터 세션 내내 남는다**(캐시된 공유 객체). 모델의 AnimationLibrary 에 동작을 얹을 땐 `duplicate(false)` 사본으로 바꿔 끼운 뒤 거기에(01 §4-22)
- 리타깃(BoneMap) 하면 본 이름이 표준 휴머노이드로 바뀐다 — 새끼손가락은 `Pinky` 가 아니라 `Little`. `AnimationLibrary.add_animation` 은 이름에 `/ : , [` 를 못 쓴다
- 에디터가 열고 있는 프로젝트에 CLI `--import` 를 같이 돌리지 말 것(둘 다 `.godot/` 를 쓴다). res:// 경로가 같으면 `.import` 파일은 다른 사본에서 만들어 복사해도 맞는다(경로 해시)
- 스크립트의 `extends` 는 노드 클래스의 **부모 쪽**이어야 붙는다 — Node2D 상속 스크립트는 CanvasGroup 에도 붙지만 반대는 안 됨(M2)
- 컨테이너 안에서 자식 위치를 직접 잡으려면(확대·이동) 맨 `Control` 을 부모로

**GDScript**
- Object 가상함수 이름(`_get`, `_set` 등)을 헬퍼로 쓰지 말 것
- 람다 파라미터는 Variant — 타입 명시
- `a if cond else b` 를 줄바꿈하려면 `\` (이건 GDScript 에선 정상. bash heredoc 에선 문제 — S5)
